# @jotl/convert

[English](../README.md) · **简体中文**

包页与市场页只显示英文版。

把 JSON Schema 转成 TypeScript 声明再转回来，约束一个不丢；把旧版 JSON Schema、OpenAPI 与凤蝶 schema 升级为 JSON Schema 2020-12 和 Jotl。

适合用 JSON Schema 维护表单或接口契约、又需要 TS 类型的团队，以及手里还有旧方言 schema 的项目。光靠类型写不出 `maxLength: 20`，也写不出「这个枚举值叫 Admin」，所以单向生成器会丢掉这些关键字。本包把类型表达不了的关键字都写成 JSDoc 标签，`tsToSchema` 读回来的 schema 与原文深度相等。旧版升级时每处改写都报一条诊断，拿到的是一份变更清单，而不是悄悄改掉。

## 看看输出

把一份 2020-12 schema 交给 `schemaToTs`：

```ts
import { schemaToTs } from "@jotl/convert";

const schema = {
  $schema: "https://json-schema.org/draft/2020-12/schema",
  $ref: "#/$defs/User",
  "x-ui": { version: 1 },
  $defs: {
    User: {
      type: "object",
      properties: {
        name: { title: "Name", type: "string", maxLength: 20 },
        age: { type: "integer", minimum: 0 },
        role: { type: "string", oneOf: [{ const: "admin", title: "Admin" }, { const: "guest", title: "Guest" }] },
      },
      required: ["name"],
    },
  },
};

console.log(schemaToTs(schema).value);
```

输出：

```ts
// Generated by Jotl. Do not edit.

export interface User {
  /**
   * @title Name
   * @maxLength 20
   */
  name: string;
  /**
   * @asType integer
   * @minimum 0
   */
  age?: number;
  /**
   * @enumTitles `{"admin":"Admin","guest":"Guest"}`
   */
  role?: "admin" | "guest";
}

export default User;
```

把这段文本交给 `@jotl/convert/from-ts` 的 `tsToSchema`，得到与 `schema` 深度相等的结果，没有诊断。

## 快速开始

1. 在新目录里安装：

   ```sh
   mkdir convert-demo && cd convert-demo && pnpm add @jotl/convert
   ```

2. 把一份 schema 转成 TS：

   ```sh
   node --input-type=module -e 'import { schemaToTs } from "@jotl/convert"; console.log(schemaToTs({ $ref: "#/$defs/Tag", $defs: { Tag: { type: "string", maxLength: 10 } } }).value)'
   ```

   输出里是 `export type Tag = string;`，JSDoc 带 `@maxLength 10`。

## 能得到什么

- **schema 与 TS 往返互转**：`schemaToTs` 把约束、标题与 `x-ui` 写成 JSDoc 标签，`tsToSchema` 原样还原；见 [JSON Schema 与 TypeScript 互转](docs/ts-conversion.md) 与 [标签协议](docs/tag-protocol.md)。
- 标签不被 lint 误报：TSDoc 预设与 eslint-plugin-jsdoc 标签表让检查工具认识这些自定义标签；见 [配置 TSDoc 与 ESLint](docs/lint-presets.md)。
- 可选 typia 输出：`typiaTags: true` 把约束写成 `tags.MaxLength<20>` 这类 typia 类型标签。
- 升级旧版并给出变更清单：draft-04 到 2019-09 的 schema，以及 OpenAPI 3.0 / Swagger 2.0 的 Schema Object 升级为 2020-12，可跨文件，每处改写一条 info 诊断；见 [升级旧版 JSON Schema](docs/upgrade.md)。
- 凤蝶迁移到 Jotl：凤蝶 schema 源码或 umo JSON 转成 Jotl，Jotl 没有写法的信息保留在 `x-fengdie`；见 [迁移凤蝶 schema](docs/fengdie-migration.md)。

## 不适合的场景

`tsToSchema` 只按语法读单个声明文件：泛型、条件类型、映射类型、接口继承和导入的类型都不转换，不能把任意业务类型变成 schema。它还会加载 TypeScript 编译器；主入口 `@jotl/convert` 不加载，浏览器产物应只用主入口。不支持 draft-03。在命令行里转换请用 [`jotl` CLI](../../cli/zh/README.md) 的 `jotl convert` 与 `jotl migrate-schema`。
