# JSON Schema 与 TypeScript 互转

[English](../../docs/ts-conversion.md) · **简体中文**

本页讲怎样用 `schemaToTs` 把 JSON Schema 2020-12 文档转成 TS 声明，再用 `tsToSchema` 把声明文件读回来。前提是已按 [README](../README.md#快速开始) 装好 `@jotl/convert`。

`schemaToTs` 把类型表达不了的关键字写成 JSDoc 标签，`tsToSchema` 读回同一套写法，两个方向共用一份 [标签协议](./tag-protocol.md)。**生成的 `.d.ts` 经 `tsToSchema` 读回后与原 schema 深度相等**；共享样例 `fixtures/*/types.d.ts` 是测试的比对基准。

## 转换 schema 并读回

```ts
import { schemaToTs } from "@jotl/convert";
import { tsToSchema } from "@jotl/convert/from-ts";

const schema = {
  $schema: "https://json-schema.org/draft/2020-12/schema",
  $ref: "#/$defs/Page",
  "x-ui": { version: 1 },
  $defs: {
    Page: {
      type: "object",
      properties: {
        title: { title: "标题", type: "string", maxLength: 20, default: "欢迎", errorMessage: { maxLength: "最多 20 字" } },
        count: { type: "integer", minimum: 1 },
        mode: { type: "string", oneOf: [{ const: "light", title: "浅色" }, { const: "dark", title: "深色" }] },
        cover: { type: "string", format: "uri", "x-ui": { widget: "image" } },
      },
      required: ["title"],
    },
  },
};

const ts = schemaToTs(schema); // diagnostics: []
const back = tsToSchema(ts.value!, { fileName: "page.d.ts" }); // back.value 与 schema 深度相等
```

`ts.value`（默认语言 `en` 下）：

```ts
// Generated by Jotl. Do not edit.

export interface Page {
  /**
   * @title 标题
   * @maxLength 20
   * @defaultValue "欢迎"
   * @errorMessage `{"maxLength":"最多 20 字"}`
   */
  title: string;
  /**
   * @asType integer
   * @minimum 1
   */
  count?: number;
  /**
   * @enumTitles `{"light":"浅色","dark":"深色"}`
   */
  mode?: "light" | "dark";
  /**
   * @format uri
   * @widget image
   */
  cover?: string;
}

export default Page;
```

schema 根上带 `"x-ui": { version: 1 }`，因为 `@jotl/core` 的编译器会写它，`tsToSchema` 在有根类型时也会写回。去掉它，往返结果就恰好差这一个键。

## 选择入口

`schemaToTs` 来自主入口 `@jotl/convert`，`tsToSchema` 只从子路径 `@jotl/convert/from-ts` 导出。本包依赖固定版本的 `typescript@6.0.3`，只有 `tsToSchema` 用到它。

主入口（含 `schemaToTs` 与全部迁移 API）不引用 `typescript`，只用主入口的浏览器产物与插件不会打包编译器。从 `@jotl/convert/from-ts` 导入会把整个编译器打进产物；[`apps/playground/vite.config.ts`](../../../../apps/playground/vite.config.ts) 的构建守卫在产物混入 `typescript` 时让构建失败。`tsToSchema` 在浏览器中运行尚未验证，见[已知限制](#已知限制)。

## API

| 导出 | 签名 | 说明 |
|---|---|---|
| `schemaToTs` | `(schema, options?: SchemaToTsOptions) => Result<string>` | 输入不是 schema 对象时报 `JOTL2001`；无法表达的关键字丢弃并报 `JOTL2002` warning，不影响输出 |
| `SchemaToTsOptions.typiaTags` | `boolean`，默认 `false` | 见 [输出 typia 类型标签](#输出-typia-类型标签) |
| `SchemaToTsOptions.defaultExport` | `string`，`$defs` 的键 | 默认导出的类型；取 `@jotl/core` 的 `compile` 结果中的 `defaultExport`（Jotl 的 `<default/>`）。缺省或不在 `$defs` 中时默认导出根；与根不同时根类型注释写 `@root` |
| `tsToSchema`（只从 `@jotl/convert/from-ts` 导出） | `(source, options?: TsToSchemaOptions) => TsToSchemaResult` | 输入为单个声明文件的文本；有错误级诊断时 `value` 为 `undefined`。`TsToSchemaResult` 在 `Result<JsonSchemaObject>` 之外另带 `defaultExport?`（默认导出的类型名，不进 schema；打印 Jotl 时传给 `@jotl/core` 的 `print(schema, { defaultExport })` 以写出 `<default/>`） |
| `TsToSchemaOptions.fileName` | `string` | 只用作诊断位置中的文件名 |
| `GENERATED_HEADER` `GENERATED_HEADER_EN` | `string` | 生成文件的首行（`// 由 Jotl 生成, 不要手改.` / `// Generated by Jotl. Do not edit.`），按全局语言取用 |
| `CUSTOM_TAGS` | `readonly CustomTagDefinition[]` | 协议定义的自定义标签名与语法（`block` / `modifier`） |
| `TS_DIAGNOSTICS` `tsDiagnostic` `TsDiagnosticCode` | | 代码表与诊断工厂 |
| `@jotl/convert/eslint` 的 `definedTags` | `readonly string[]` | 见 [配置 TSDoc 与 ESLint](./lint-presets.md) |
| `@jotl/convert/tsdoc.json` | TSDoc 配置文件 | 见 [配置 TSDoc 与 ESLint](./lint-presets.md) |

## schemaToTs 输出什么

输出的排版（生成文件头、声明顺序、缩进、默认导出）见 [共享样例集 README](../../../../fixtures/zh/README.md) 的「TS 输出格式」。根 schema 不是指向 `$defs` 的 `$ref` 时，输出为 `Root` 类型并默认导出，报 `JOTL2006` warning。

没有 TS 写法的关键字丢弃并报 `JOTL2002`，具体是哪些见 [标签协议](./tag-protocol.md)。

## tsToSchema 接受什么

`tsToSchema` 只按语法树转换，不做类型检查。根取注释带 `@root` 的声明，没有时取默认导出。

- 支持：`interface`、`type`、`export default`（含 `export { X as default }`）、`Array<T>`、`Record<string, T>`、元组与 `readonly`。具名元组的成员名还原为该位置的 `title`。
- 联合：可区分联合输出为 `oneOf`，含 `null` 的字面量联合输出为 `anyOf: [枚举, { type: "null" }]`，`(A | B) | null` 输出为 `anyOf: [A 与 B 的联合, { type: "null" }]`，其余联合输出为 `anyOf`。
- 交叉类型只接受引用，与至多一个其他类型及 typia 标签组合（见 [标签协议](./tag-protocol.md) 与 [输出 typia 类型标签](#输出-typia-类型标签)）。多个对象字面量（如 `{ a: 1 } & { b: 2 }`）只含属性签名且属性名互不相同时，合并为一个开放对象（合并 `properties` 与 `required`）。其余交叉（属性同名、含索引签名或方法等）报 `JOTL2106`。
- 不支持的写法报错误级诊断：泛型、条件类型、映射类型、函数与方法、接口继承、`enum` 等其他声明、计算属性名。
- 导入声明只报 `JOTL2108` warning，其他文件里的类型不会被转换。

## 输出 typia 类型标签

`typiaTags: true` 时，typia 能表达的约束写成类型交叉。产物开头加 `import { tags } from "typia";`；已有类型名为 `tags` 时改用别名导入，一个标签都没用到时不导入。

- `type: "integer"` → `tags.Type<"int32">`（上下界都在 int32 范围内）或 `tags.Type<"int64">`，不再写 `@asType`。
- 数值与长度约束 → `tags.Minimum<1>` 等同名标签；`pattern` → `tags.Pattern`；`uniqueItems` → `tags.UniqueItems`；`contentMediaType` → `tags.ContentMediaType`。
- `format` 只改写 typia 支持的格式（清单是 [`src/ts/typia.ts`](../../src/ts/typia.ts) 的 `TYPIA_FORMATS`），其余（如 `color`）仍写 `@format`。
- `default` 为字符串、数字、布尔或它们组成的数组时 → `tags.Default`，否则仍写 `@defaultValue`。
- `x-ui` 为对象时 → `tags.JsonSchemaPlugin<{ "x-ui": ... }>`。
- 可空类型只给非 `null` 部分加标签。接口声明本身不能挂标签，其约束仍写 JSDoc。元素级约束在此模式下可以表达。

产物按 `typia@15.1.0` 的类型定义检查为零类型错误；其他 typia 版本的 `tags.Format` 取值可能不同。

`tsToSchema` 读取经 `import { tags } from "typia"`（含别名）导入的标签，还原为上述关键字；`tags.Type<"int32" | "int64" | "uint32" | "uint64">` 把 `number` 改为 `integer`。可空的 `(T & tags.X) | null` 读回为 `type: [T, "null"]`，所以 typia 模式的产物可以往返。导入声明仍报 `JOTL2108` warning；其他 typia 标签，以及没有导入时的 `tags.X`，报 `JOTL2106`。

## 解读诊断

`JOTL20xx` 来自 schema → TS，`JOTL21xx` 来自 TS → schema；代码表是 [`src/ts/diagnostics.ts`](../../src/ts/diagnostics.ts) 的 `TS_DIAGNOSTICS`。针对 TS 源码的诊断带行列，`location.kind = "source"`；针对 schema 的诊断带指向节点的 JSON Pointer。

## 已知限制

- **元组各位置的 title 只能写成成员名。** TS 元组元素没有放注释的位置，`schemaToTs` 把 `prefixItems` 各位置的 `title` 写成具名元组成员（`[开始: string, 结束: string]`）。TS 要求元组成员全部具名或全不具名，所以只在每个位置都有 `title`、且都是标识符而不是保留字时可行；否则这些 `title` 丢弃并报 `JOTL2002`（见 [标签协议](./tag-protocol.md)）。`.d.ts` 的读者需要这些含义时，写进数组本身的 `description`。
- **`tsToSchema` 未在浏览器中测试。** 它用自定义 compiler host 调用 `typescript@6.0.3` 的经典 API，只在 Node.js 下有测试覆盖。请在 Node.js 中运行；要在浏览器中使用，先在目标浏览器里自测。
