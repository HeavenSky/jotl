# @jotl/convert

**English** · [简体中文](./zh/README.md)

Turn JSON Schema into TypeScript declarations and back without losing constraints, and bring legacy JSON Schema, OpenAPI and Fengdie schemas up to JSON Schema 2020-12 and Jotl.

This package is for teams that keep form or API contracts in JSON Schema and also need TS types, or that still hold schemas in older dialects. A type alone cannot say `maxLength: 20` or "this enum value is labeled Admin", so one-way generators drop those keywords. Here every keyword a type cannot express becomes a JSDoc tag, and `tsToSchema` reads the file back to a deeply equal schema. Legacy upgrades report every rewrite as a diagnostic, so you get a change list instead of a silent rewrite.

## See the output

Give `schemaToTs` a 2020-12 schema:

```ts
import { schemaToTs } from "@jotl/convert";

const schema = {
  $schema: "https://json-schema.org/draft/2020-12/schema",
  $ref: "#/$defs/User",
  "x-ui": { version: 1 },
  $defs: {
    User: {
      type: "object",
      properties: {
        name: { title: "Name", type: "string", maxLength: 20 },
        age: { type: "integer", minimum: 0 },
        role: { type: "string", oneOf: [{ const: "admin", title: "Admin" }, { const: "guest", title: "Guest" }] },
      },
      required: ["name"],
    },
  },
};

console.log(schemaToTs(schema).value);
```

It prints:

```ts
// Generated by Jotl. Do not edit.

export interface User {
  /**
   * @title Name
   * @maxLength 20
   */
  name: string;
  /**
   * @asType integer
   * @minimum 0
   */
  age?: number;
  /**
   * @enumTitles `{"admin":"Admin","guest":"Guest"}`
   */
  role?: "admin" | "guest";
}

export default User;
```

Passing this text to `tsToSchema` from `@jotl/convert/from-ts` returns a schema deeply equal to `schema`, with no diagnostics.

## Get started

1. Install the package in a new folder:

   ```sh
   mkdir convert-demo && cd convert-demo && pnpm add @jotl/convert
   ```

2. Convert a schema to TS:

   ```sh
   node --input-type=module -e 'import { schemaToTs } from "@jotl/convert"; console.log(schemaToTs({ $ref: "#/$defs/Tag", $defs: { Tag: { type: "string", maxLength: 10 } } }).value)'
   ```

   You see `export type Tag = string;` with `@maxLength 10` in its JSDoc.

## What you get

- **Round trip between schema and TS**: `schemaToTs` writes constraints, titles and `x-ui` as JSDoc tags, and `tsToSchema` restores them; see [Convert between JSON Schema and TypeScript](docs/ts-conversion.md) and the [tag protocol](docs/tag-protocol.md).
- Lint-clean tags: a TSDoc preset and an eslint-plugin-jsdoc tag list stop linters from flagging the custom tags; see [Configure TSDoc and ESLint](docs/lint-presets.md).
- Optional typia output: `typiaTags: true` writes constraints as typia type tags such as `tags.MaxLength<20>`.
- Legacy upgrade with a change list: draft-04 to 2019-09 schemas and OpenAPI 3.0 / Swagger 2.0 Schema Objects become 2020-12, across files if needed, with one info diagnostic per rewrite; see [Upgrade legacy JSON Schema](docs/upgrade.md).
- Fengdie to Jotl: Fengdie schema source or umo JSON becomes Jotl, and information Jotl has no syntax for is kept in `x-fengdie`; see [Migrate Fengdie schemas](docs/fengdie-migration.md).

## Where it does not fit

`tsToSchema` reads one declaration file by syntax only: generics, conditional and mapped types, interface inheritance and imported types are not converted, so it does not turn arbitrary application types into schemas. It also loads the TypeScript compiler; the main entry `@jotl/convert` does not, and it is the one to use in browser bundles. draft-03 schemas are not supported. For command-line conversion use `jotl convert` and `jotl migrate-schema` from the [`jotl` CLI](../cli/README.md).
