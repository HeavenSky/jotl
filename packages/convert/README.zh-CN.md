# @jotl/convert

[English](./README.md) · **简体中文**

在 JSON Schema 与 TS 声明(类型 + JSDoc 标签)之间互转, 手写或校对 Jotl 生成的 `.d.ts` 标签, 为 TSDoc / ESLint 配置 Jotl 标签, 在代码中把旧版 JSON Schema 升级到 2020-12, 把凤蝶 schema 迁移为 Jotl, 或解读 `JOTL20xx` / `JOTL21xx`(TS 互转), `JOTL3xxx`(升级), `JOTL8xxx`(凤蝶)诊断时读本页; 对应 `packages/convert`.
本包分两部分: TS 互转(`src/ts/`), 以及旧版 JSON Schema / OpenAPI 升级与凤蝶迁移(`src/migrate/`).
迁移的命令行入口是 `jotl migrate-schema`(自动判定输入类型), 见 `packages/cli/README.zh-CN.md`.

诊断消息与生成文字(生成文件头, 默认弃用说明, 凤蝶分组标题, 输入类型的判定依据)随 `@jotl/core` 的全局语言: 默认英文(`en`), 要中文时调用 `@jotl/core` 的 `setLocale("zh-CN")`.

## 安装

```sh
pnpm add @jotl/convert
```

依赖固定版本的 `typescript@6.0.3`, 只有 `tsToSchema`(子路径 `@jotl/convert/from-ts`)用到它.

## TS 互转

`schemaToTs` 把 JSON Schema 2020-12 输出为 TS 声明, 类型表达不了的关键字写成 JSDoc 标签; `tsToSchema` 读回同一套写法. 两个方向共用一份标签协议, 生成的 `.d.ts` 经 `tsToSchema` 往返后与原 schema 深度相等(共享样例 `fixtures/*/types.d.ts` 是比对基准).

### 最小示例

```ts
import { schemaToTs } from "@jotl/convert";
import { tsToSchema } from "@jotl/convert/from-ts";

const schema = {
  $schema: "https://json-schema.org/draft/2020-12/schema",
  $ref: "#/$defs/Page",
  $defs: {
    Page: {
      type: "object",
      properties: {
        title: { title: "标题", type: "string", maxLength: 20, default: "欢迎", errorMessage: { maxLength: "最多 20 字" } },
        count: { type: "integer", minimum: 1 },
        mode: { type: "string", oneOf: [{ const: "light", title: "浅色" }, { const: "dark", title: "深色" }] },
        cover: { type: "string", format: "uri", "x-ui": { widget: "image" } },
      },
      required: ["title"],
    },
  },
};

const ts = schemaToTs(schema); // diagnostics: []
const back = tsToSchema(ts.value!, { fileName: "page.d.ts" }); // back.value 与 schema 深度相等
```

`ts.value`:

```ts
// 由 Jotl 生成, 不要手改.

export interface Page {
  /**
   * @title 标题
   * @maxLength 20
   * @defaultValue "欢迎"
   * @errorMessage `{"maxLength":"最多 20 字"}`
   */
  title: string;
  /**
   * @asType integer
   * @minimum 1
   */
  count?: number;
  /**
   * @enumTitles `{"light":"浅色","dark":"深色"}`
   */
  mode?: "light" | "dark";
  /**
   * @format uri
   * @widget image
   */
  cover?: string;
}

export default Page;
```

### TS 互转的公开 API

| 导出 | 签名 | 说明 |
|---|---|---|
| `schemaToTs` | `(schema, options?: SchemaToTsOptions) => Result<string>` | 输入不是 schema 对象时报 `JOTL2001`; 无法表达的关键字丢弃并报 `JOTL2002` warning, 不影响输出 |
| `SchemaToTsOptions.typiaTags` | `boolean`, 默认 `false` | 见下文 typia 一节 |
| `SchemaToTsOptions.defaultExport` | `string`, `$defs` 的键 | 默认导出的类型; 取 `@jotl/core` 的 `compile` 结果的 `defaultExport`(Jotl 的 `<default/>`). 缺省或不在 `$defs` 中时默认导出根; 与根不同时根类型注释写 `@root` |
| `tsToSchema`(只从 `@jotl/convert/from-ts` 导出) | `(source, options?: TsToSchemaOptions) => TsToSchemaResult` | 输入为单个声明文件文本; 有错误级诊断时 `value` 为 `undefined`. `TsToSchemaResult` 在 `Result<JsonSchemaObject>` 上另带 `defaultExport?`(默认导出的类型名, 不进 schema; 打印 Jotl 时传给 `@jotl/core` 的 `print(schema, { defaultExport })` 以写出 `<default/>`) |
| `TsToSchemaOptions.fileName` | `string` | 只用于诊断位置中的文件名 |
| `GENERATED_HEADER` `GENERATED_HEADER_EN` | `string` | 生成文件的首行(`// 由 Jotl 生成, 不要手改.` / `// Generated by Jotl. Do not edit.`), 按全局语言取用 |
| `CUSTOM_TAGS` | `readonly CustomTagDefinition[]` | 协议定义的自定义标签名与语法(`block` / `modifier`) |
| `TS_DIAGNOSTICS` `tsDiagnostic` `TsDiagnosticCode` | | 代码表与诊断工厂 |
| `@jotl/convert/eslint` 的 `definedTags` | `readonly string[]` | 见下文 lint 一节 |
| `@jotl/convert/tsdoc.json` | TSDoc 配置文件 | 见下文 lint 一节 |

输出的排版(生成头, 声明顺序, 缩进, 默认导出)见 `fixtures/README.zh-CN.md` 的 "TS 输出格式". 根 schema 不是指向 `$defs` 的 `$ref` 时输出为 `Root` 类型并默认导出, 报 `JOTL2006` warning.

`tsToSchema` 只按语法树转换, 不做类型检查; 根取注释带 `@root` 的声明, 没有时取默认导出; 支持 `interface`, `type`, `export default`(含 `export { X as default }`), `Array<T>`, `Record<string, T>`, 元组与 `readonly`. 可区分联合输出为 `oneOf`, 含 `null` 的字面量联合为 `anyOf: [枚举, { type: "null" }]`, 其余联合为 `anyOf`. 交叉类型只接受引用, 至多一个其他类型与 typia 标签的组合(见标签协议与 typia 一节); 多个对象字面量(如 `{ a: 1 } & { b: 2 }`)只含属性签名且属性名互不相交时合并为一个开放对象(合并 `properties` 与 `required`); 其余交叉(属性同名, 含索引签名或方法等)报 `JOTL2106`. 不支持的写法(泛型, 条件类型, 映射类型, 函数与方法, 接口继承, `enum` 等其他声明, 计算属性名)报错误级诊断; 导入声明只报 `JOTL2108` warning, 跨文件的类型不会被转换.

### 标签协议

关键字与 TS 写法的对应:

| JSON Schema | TS 写法 |
|---|---|
| `description` | JSDoc 正文 |
| `title` | `@title 文本` |
| `$comment` | `@privateRemarks 文本` |
| `type: "integer"` | 类型写 `number`, 加 `@asType integer`(节点为枚举或常量时不写) |
| `minLength` `maxLength` `minimum` `maximum` `exclusiveMinimum` `exclusiveMaximum` `multipleOf` `minItems` `maxItems` `minProperties` `maxProperties` | 同名标签, 取值为数字 |
| `format` `contentMediaType` `contentEncoding` | 同名标签, 取值为文本 |
| `pattern` | `@pattern`, 取值为正则 |
| `uniqueItems: true` `writeOnly: true` | `@uniqueItems` `@writeOnly`(修饰标签, 无取值) |
| `readOnly: true` | `@readonly` |
| `deprecated: true`(+ `x-deprecatedReason`) | `@deprecated 原因`; 无原因时写默认文本, `zh-CN` 为 `已弃用.`, `en` 为 `Deprecated.`; 两种文本读回都不产生 `x-deprecatedReason` |
| `default` | `@defaultValue JSON` |
| `examples` | 每个示例一个 `@example JSON` |
| 带标签枚举 `oneOf: [{ const, title }]` | 类型为字面量联合, 加 `@enumTitles` JSON 对象(键为成员值, 字符串取其本身, 其余取 JSON 文本); 数组元素是枚举时写在数组属性上 |
| 枚举成员的 `description` | `@enumDescriptions` JSON 对象, 键同 `@enumTitles` |
| 每项只含 `$ref` 的 `allOf` | 交叉类型 `X & Y & 其余部分`, 如可区分联合分支 `X & { kind: "x" }`; 没有其余部分且只有一个引用时写 `X & unknown` |
| 可区分联合分支的 `title` | `@branchTitles` JSON 数组, 按分支顺序, 无 `title` 的分支为 `null`; 只在联合节点可写注释时输出 |
| 同时有 `properties` 与 `additionalProperties` | 索引签名写 `(额外类型) \| 属性类型...`, 可选属性另加 `undefined`; 读取时只取括号中的额外类型 |
| `x-valueFormat`(日期组件的存储格式) | `@valueFormat 格式`, 取值为文本 |
| 根 `$ref` 指向的类型与默认导出不同 | 根类型注释加 `@root`(修饰标签, 无取值) |
| 根 `$id`(只在根类型上) | `@id URI`, 取值为文本 |
| 根 `x-ui.rules`(只在根类型上) | `@rules 规则数组`, 取值为 JSON |
| 根 `x-ui.widgets`(扩展组件模块, 只在根类型上) | `@widgets 模块表`, 取值为 JSON 对象 |
| `x-ui` | 只有 `widget` 时 `@widget 名字`, 否则 `` @ui `{...}` `` |
| 数组元素的 `x-ui` | 写在数组属性上: 只有 `widget` 时 `@itemWidget 名字`, 否则 `` @itemUi `{...}` ``; 第 n 个标签作用于第 n 层元素(`items`, `items.items`...), 跳过的层级写 `` @itemUi `{}` `` |
| `errorMessage` | `@errorMessage JSON`(字符串或对象) |

标签按 `docs/spec/jotl.md` 规范化规则 7 的关键字顺序排列. 除数组元素的 `x-ui` 外, 元素级约束与注解(如数组元素上的 `maxLength`)没有可挂注释的位置, 非 typia 模式下丢弃并报 `JOTL2002`.
Jotl 扩展关键字 `x-decimals` `x-decimalRange`, 以及 `contentSchema` `propertyNames` 与含非引用成员的 `allOf`, 没有对应写法, 同样丢弃并报 `JOTL2002`. 编译器为内置组件生成的固定形态不报: `money` `bigint` 值对象(`properties.type` 为 `money` 或 `bigint` 常量)上的 `additionalProperties: false` `x-decimalRange` `x-decimals`, 以及不能写注释的位置(如数组元素, 联合分支)上可区分联合分支的 `title`.
根 `$id` 与根 `x-ui.rules`(根上只含 `version` 与 `rules` 的 `x-ui` 属于文档层面)写成根类型注释上的 `@id` `@rules`(根 `x-ui.widgets` 同样写成 `@widgets`); 没有根时丢弃并报 `JOTL2002`. 根类型(带 `@root` 的声明, 没有时为默认导出)以外写 `@root` `@id` `@rules` 报 `JOTL2115`; 有根时 `tsToSchema` 于根写入 `x-ui: { version: 1 }` 与读到的 `rules`, 与编译器一致.

取值编码:

- 文本取值(正文, `@title` 等): TSDoc 语法字符(反斜杠, `@`, `{`, `}`, `<`, `>` 与反引号)前加反斜杠转义, `*/` 写成 `*\/`.
- JSON 取值: 对象, 以及含 TSDoc 语法字符或反斜杠的值, 用反引号包裹; 其余直接写 JSON(如 `"欢迎"` `1`).
- 正则: 写在反引号中; 含反引号, 换行, `*/`, 以引号开头, 首尾有空白或为空串时, 改写为反引号中的 JSON 字符串.
- 示例: 对象与含对象的数组写成 `json` 代码块.

读取时额外接受: 别名 `@default` `@readOnly` `@examples` `@comment` `@description`(标签名不区分大小写); JSON 取值的反引号可省略; 不是合法 JSON 的取值按字符串处理并报 `JOTL2113` warning; TSDoc 标准标签(如 `@remarks` `@see`)静默忽略, 未知标签报 `JOTL2114` warning; 标签用在不适用的类型上报 `JOTL2115` warning; `@asType` 只接受 `integer`, 其余值报 `JOTL2118` warning.

### typia 类型标签

`typiaTags: true` 时, typia 能表达的约束改写为类型交叉, 产物开头加 `import { tags } from "typia";`(类型名占用了 `tags` 时改用别名导入, 没有用到时不导入):

- `type: "integer"` → `tags.Type<"int32">`(上下界都在 int32 范围内)或 `tags.Type<"int64">`, 不再写 `@asType`.
- 数字与长度约束 → `tags.Minimum<1>` 等同名标签; `pattern` → `tags.Pattern`; `uniqueItems` → `tags.UniqueItems`; `contentMediaType` → `tags.ContentMediaType`.
- `format` 只改写 typia 支持的格式(清单见 `packages/convert/src/ts/typia.ts` 的 `TYPIA_FORMATS`), 其余(如 `color`)仍写 `@format`.
- `default` 为字符串, 数字, 布尔或其数组时 → `tags.Default`, 否则仍写 `@defaultValue`.
- `x-ui` 为对象时 → `tags.JsonSchemaPlugin<{ "x-ui": ... }>`.
- 可空类型只给非 `null` 部分加标签; 接口声明本身不能挂标签, 其约束仍写 JSDoc. 元素级约束在此模式下可以表达.

前提: 产物按 `typia@15.1.0` 的类型定义校验为零类型错误, 其他 typia 版本的 `tags.Format` 取值可能不同. `tsToSchema` 读取 `import { tags } from "typia"`(含别名)导入的标签并还原为上述关键字(`tags.Type<"int32" | "int64" | "uint32" | "uint64">` 把 `number` 改为 `integer`), 可空的 `(T & tags.X) | null` 读回 `type: [T, "null"]`, typia 模式的产物可以往返; 导入声明仍报 `JOTL2108` warning, 其他 typia 标签与未导入时的 `tags.X` 报 `JOTL2106`.

### TSDoc 与 ESLint 配置

不加载预设时, TSDoc 与 eslint-plugin-jsdoc 会把协议中的自定义标签报为未知标签.

TSDoc(如 eslint-plugin-tsdoc, API Extractor)在项目的 `tsdoc.json` 中继承预设:

```json
{
  "$schema": "https://developer.microsoft.com/json-schemas/tsdoc/v0/tsdoc.schema.json",
  "extends": ["@jotl/convert/tsdoc.json"]
}
```

eslint-plugin-jsdoc 用 `definedTags`(自定义标签加 `defaultValue` `privateRemarks`):

```js
import { definedTags } from "@jotl/convert/eslint";

export default [{ rules: { "jsdoc/check-tag-names": ["error", { definedTags }] } }];
```

`tsdoc.json` 的 `extends` 已有测试覆盖; 两个 ESLint 插件加载预设后的表现尚未实测, 见根目录 `TODO.md` 的 "确定不修".

### 在浏览器中使用

主入口 `@jotl/convert`(含 `schemaToTs` 与全部迁移 API)不引用 `typescript`, 只用主入口的浏览器产物与插件不会打包编译器.
`tsToSchema` 依赖 `typescript`, 只从 `@jotl/convert/from-ts` 导出; 从这个子路径导入会把整个编译器打进产物, `apps/playground/vite.config.ts` 的构建守卫在产物混入 `typescript` 时让构建失败.
`tsToSchema` 在浏览器中运行尚未验证, 见根目录 `TODO.md` 的 "确定不修".

## 升级: 旧版 JSON Schema → 2020-12

识别输入的版本, 逐级改写到 2020-12(被 `$ref` 指向的未知关键字下的子 schema 同样升级), 同步调整受改名影响的 `$ref`, 根上写入 2020-12 的 `$schema` 并按规范化顺序排列关键字. 每处改写报一条 info 诊断, 可直接当作变更清单.

### 升级的最小示例

```ts
import { upgradeSchema } from "@jotl/convert";

const result = upgradeSchema({
  $schema: "http://json-schema.org/draft-04/schema#",
  id: "https://x.test/a.json",
  type: "object",
  properties: { n: { $ref: "#/definitions/n" } },
  definitions: { n: { type: "number", minimum: 0, exclusiveMinimum: true } },
});
// result.value.schema:
// { $schema: "https://json-schema.org/draft/2020-12/schema", $id: "https://x.test/a.json", type: "object",
//   properties: { n: { $ref: "#/$defs/n" } }, $defs: { n: { type: "number", exclusiveMinimum: 0 } } }
// result.value.version: "draft-04", result.value.versionSource: "declared"
// result.diagnostics: JOTL3101 JOTL3105 JOTL3102 JOTL3120 JOTL3119, 均为 info
```

跨文件引用用 `upgradeDocuments`, 由调用方提供按 URI 取文档的回调:

```ts
import { upgradeDocuments } from "@jotl/convert";

const result = await upgradeDocuments("https://x.test/main.json", {
  load: async (uri) => ({ value: await fetchJson(uri), diagnostics: [] }),
});
// result.value.documents: 键为文档 URI, 按加载顺序排列, 第一项为入口; 每个文档按自己的 $schema 识别版本
```

### 版本识别

`detectVersion(schema, options?)` 按以下顺序取第一个成立的项, `upgradeSchema` 与 `upgradeDocuments` 内部同样使用:

1. `$schema` 可识别(http 与 https, 带或不带空片段, 以及对应的 hyper-schema): `versionSource` 为 `"declared"`; 与 `version` 选项不同时以 `$schema` 为准并报 `JOTL3006`. JSON Schema 稳定版 v1 的 `https://json-schema.org/v1`(及 `/v1/<年份>`)按 `2020-12` 读取, 输出时 `$schema` 改写为 2020-12(`JOTL3119`).
2. 调用方给了 `version`: `"specified"`; 此时若 `$schema` 存在但无法识别, 报 `JOTL3004`.
3. 按特征关键字推断: `"inferred"`, 报 `JOTL3007`(info). 有 Swagger 特征(如 `x-nullable`)时取 `swagger-2.0`, 有 OpenAPI 3.0 特征(如 `nullable`)时取 `openapi-3.0`, 否则有旧版特征时取其中对应的最低版本, 只有新版特征时取它们共同支持的最低版本.

- 既无 `$schema` 也无可区分的关键字时报 `JOTL3001` error, 需要用 `version` 指定; 例如 `upgradeSchema({ type: "string" })` 失败, `upgradeSchema({ type: "string" }, { version: "draft-07" })` 成功.
- draft-03 不支持, 报 `JOTL3002`.
- 可用的版本取值见 `src/migrate/upgrade/versions.ts` 的 `SCHEMA_VERSIONS`, 用 `isSchemaVersion` 判断字符串是否合法.

### 升级的公开 API

| 导出 | 作用 |
|---|---|
| `upgradeSchema(schema, options?)` | 升级单个文档, 不修改输入; 返回 `Result<UpgradedSchema>`: `{ schema, version, versionSource }`. 有 error 时 `value` 为 `undefined` |
| `upgradeDocuments(entry, options)` | 从入口 URI 开始升级它及其 `$ref` 可达的全部文档, 按目标文档的指针映射改写跨文档引用; 返回 `Promise<Result<UpgradedDocuments>>`: `{ entry, documents }` |
| `detectVersion(schema, options?)` | 只识别版本, 返回 `Result<VersionDetection>`: `{ version, source }` |
| `DEFAULT_UPGRADE_OPTIONS` | 选项默认值 |
| `RECURSIVE_ANCHOR_NAME` | `$recursiveAnchor: true` 改写成的 `$dynamicAnchor` 名字 |
| `UPGRADE_DIAGNOSTICS`, `upgradeDiagnostic` | 代码表与按代码生成诊断的工具 |

`UpgradeOptions`:

| 选项 | 默认 | 含义 |
|---|---|---|
| `version` | 无 | 没有可识别的 `$schema` 时采用的版本; OpenAPI 3.0 / Swagger 2.0 的 Schema Object 通常需要指定 |
| `acceptNewerKeywords` | `true` | 声明版本中不存在的高版本关键字: `true` 按 2020-12 语义保留并报 `JOTL3201`; `false` 移除并报 `JOTL3202`; `$defs` 例外, 它只是被 `$ref` 引用的容器, 两种取值下都保留 |
| `onConflict` | `"error"` | 新旧语义冲突(`JOTL33xx`)时: `"error"` 报 error 并失败; `"preferDeclared"` 按声明版本处理; `"preferLatest"` 按 2020-12 处理; 后两者报 warning 并在 `related` 写明处理方式 |
| `uri` | 无 | 文档 URI: 解析相对 `$id` / `$ref` 的基准, 并写入诊断位置的 `document` |

例: draft-07 中 `$ref` 旁写了 `minLength`, draft-07 会忽略它而 2020-12 会生效, 默认报 `JOTL3303` error; `preferDeclared` 时删除 `minLength`, `preferLatest` 时保留.

`UpgradeDocumentsOptions` 为 `UpgradeOptions` 去掉 `uri` 再加 `load: DocumentLoader`.
`DocumentLoader` 收到不含片段的绝对 URI, 返回(或 resolve 为) `Result<unknown>`:

- `value` 为文档时参与升级.
- `value` 为 `undefined` 且没有 error 诊断时, 该文档不参与升级(例如校验器已内置的元 schema), 指向它的引用保持原样.
- `value` 为 `undefined` 且有 error 时报 `JOTL3401`; 回调抛出异常时报 `JOTL3402`.

### 升级的诊断代码

代码段为 `JOTL3xxx`, 代码表是 `src/migrate/upgrade/diagnostics.ts` 的 `UPGRADE_DIAGNOSTICS`; 位置为 JSON Pointer(`location.kind === "pointer"`), 跨文档时带 `document`.

| 段 | 含义 |
|---|---|
| `30xx` | 输入与版本识别 |
| `31xx` | 逐级改写, 每处一条 info |
| `32xx` | 宽松模式: 高版本关键字的接受或移除, 高版本文档中的旧版写法 |
| `33xx` | 新旧语义冲突, 级别随 `onConflict` 变化 |
| `34xx` | 多文档加载 |

### 升级的已知限制

规范化规则 2(命名类型只在根 `$defs`)不对升级结果成立; 此项与其他限制见根目录 `TODO.md` 的 "确定不修".

## 凤蝶迁移: 凤蝶 schema → Jotl

词法与文法以凤蝶编辑器实际使用的 umo-edit-sdk 0.0.8 为准(`parse/schema.l` `schema.yy`). 流程: 源码 → 与 toJson 同构的 umo JSON → JSON Schema 2020-12 → `@jotl/core` 的 `print` 输出 Jotl.
影响迁移结果的四条口径(下文以 D1-D4 引用):

- D1 `Date` 迁为毫秒时间戳整数(`datetime[value_format: 'x']`), 凤蝶的存量数据无需转换即可通过校验.
- D2 第一层字段的 `group` 迁为根对象 `x-ui.groups`, 按 group 值渲染为分组.
- D3 没有对应 Jotl 写法的信息写入节点的 `x-fengdie`(机器可读, 往返可保留), 不写 `$comment`.
- D4 只有 `required: true` 的字段必填, 其余按凤蝶语义选填.

```ts
import { migrateFengdie } from "@jotl/convert";

const { jotl, schema, umo, diagnostics } = migrateFengdie(
  `Object(首页) {
    title(标题): String[maxLength: 20, required: true]
    start(开始): Date
  }`,
  "home.fengdie",
);
// jotl:
// Root(首页): {
//   title(标题): string[maxLength: 20]
//   start(开始)?: datetime[value_format: 'x']
// }
```

| 导出 | 作用 |
|---|---|
| `migrateFengdie(input, file?)` | input 为源码, umo JSON 文本(首个非空白字符为 `{`)或 umo JSON 对象; 返回 `{ jotl?, schema?, umo?, diagnostics }`, 有 error 时 `jotl` 为 `undefined`. `schema` 与 `jotl` 再编译的结果深度相等 |
| `fengdieToUmoJson(source, file?)` | 源码 → umo JSON, 另返回 `origins`(节点到源码位置) |
| `umoJsonToSchema(umo, { origins?, file? })` | umo JSON → 未排序的 2020-12 文档; 无 `origins` 时诊断位置为 umo JSON 中的指针 |
| `detectMigrateInput(text)` / `umoJsonFeature(json)` | 判定输入是凤蝶源码, umo JSON 还是常规 JSON Schema, 并给出依据 |
| `MIGRATE_DIAGNOSTICS` | 凤蝶诊断代码表 |

- 词法或语法错误(`JOTL8001`-`JOTL8005`)与 jison 一样在第一个错误处停止; umo JSON 解析失败与结构不合法为 `JOTL8006` `JOTL8007`.
- 其余问题都是 warning(`JOTL81xx`), 不影响结果; 只对真正丢失或改写的信息报警告, 无损保留在 `x-fengdie` 的不报. umo-edit-sdk 的 toJson 会抛错的写法(给没有元数据表的类型写元数据, 如 `Array<string>[...]` `Component[...]` 根 `OpenAction[...]`)迁移时丢弃这些元数据并报 `JOTL8118`.
- 字符串与数组按 Jotl 默认允许为空; 显式 `minLength: 0` 等于不限, 不写出.
- `x-fengdie` 在 Jotl 中写作 `x_fengdie`(D3); 结构信息占用 `type` `lottery` `public` `regExpFlags`, 同名的元数据改记为 `metaType` 等.

### 类型映射

| 凤蝶类型(umo `type`) | 2020-12 / Jotl | 说明 |
|---|---|---|
| `String`(及省略类型) `Text` `RichText` `URL` `Color` `File` `Image` `Number` `Boolean` | `string` `text` `richtext` `url` `color` `file` `image` `number` `boolean` | 未知类型名退回 `string`, 报 `JOTL8111` |
| `Date` | `datetime[value_format: 'x']` | 凤蝶编辑器为日期时间选择器, 数据是毫秒时间戳; schema 为 `{type: integer, minimum: -MAX_SAFE_INTEGER, maximum: MAX_SAFE_INTEGER, x-valueFormat: 'x', x-ui: {widget: 'datetime'}}` |
| `Enum` | `enum`; 有说明时为 `oneOf` | `multiple: true` 为多选; 2-5 项单选写 `widget: 'radio'`, 多选写 `widget: 'checkbox'`; 无成员时为字符串(`JOTL8114`) |
| `Array<string>` `Array<number>` | `array[array_item: 'string' / 'number']` | |
| `Object` `Action` `OpenAction` `Spm` | 对象 | `Spm` 固定为 `spma` `spmb` `spmc` 三个字符串 |
| `Array` | 对象数组 | |
| `Module` `ModuleArray` `命名空间.组件` `命名空间.组件[Array]` | 对象 / 对象数组 | `namespace` `component` `version` `url` `dist` 记入 `x-fengdie` |
| `Box` `Resource` `Plugin` `Animation` `Video` | 按 umo-edit-sdk mock 数据形态的对象, 不封闭 | |
| `Component` | `string` | 组件实例 id |
| 根 `Lottery` / `public` | 对象 | `x-fengdie.lottery` / `x-fengdie.public`, 不报警告 |
| `export a ... export b ...` | 各自成为 `$defs` 类型, 第一条为根 | 不是大驼峰的名字按 `print` 的规则改名, 报 `JOTL8117` |

`Component` `Box` `Resource` `Plugin` `Animation` `Video` `Action` `OpenAction` `Spm` `Module` `ModuleArray` 与命名空间类型的原类型名记入 `x-fengdie.type`.

### 元数据映射

| 凤蝶元数据 | 去向 |
|---|---|
| 说明 `(...)` / `description` | `title` / `description` |

| `required: true` | 父对象 `required`(D4) |
