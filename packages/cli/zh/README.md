# @jotl/cli

[English](../README.md) · **简体中文**

包页与市场页只显示英文版。

在终端或 CI 里把 Jotl 编译成 JSON Schema 与 TypeScript，校验 JSON 数据，迁移旧版 schema。

`jotl` 是 [Jotl](../../../zh/README.md) 的命令行工具；Jotl 是一门编译到 JSON Schema 2020-12 的简洁语言。它面向在仓库里维护表单或配置 schema、需要在脚本中构建、检查和校验它们的团队。不必再把 schema 生成器、TS 生成器和校验器串起来：一个工具同时读 Jotl、JSON Schema 与 TS 声明，每个问题都报成 `文件:行:列`，并以 `0`、`1`、`2` 退出，CI 可以直接据此判断。

## 看一次失败的校验

一份 Jotl 写的 schema，和一份违反它的数据：

```jotl
Home: {
  title: string[maxLength: 20]
  count?: integer[minimum: 1]
}
```

```json
{ "title": "Welcome", "count": 0 }
```

`jotl validate` 指出数据文件里出错的值（输出语言跟随环境，下面是中文环境的输出）：

```console
$ jotl validate home.jotl home.json
home.json#/count JOTL4003 错误: count 超出范围: 应不小于 1
  home.json:3:3 数据所在位置
home.json: 未通过
```

结论写到 stdout，诊断写到 stderr，退出码为 `1`。

## 三步拿到 TypeScript 类型

需要 Node 22 或更高版本。

1. 把命令行加进项目：

    ```sh
    pnpm add -D @jotl/cli
    ```

2. 写一个只有一个字段的 schema：

    ```sh
    printf 'Home: {\n  title: string[maxLength: 20]\n}\n' > home.jotl
    ```

3. 编译成 TS 声明：

    ```sh
    pnpm exec jotl compile home.jotl --to ts
    ```

    输出以 `// 由 Jotl 生成, 不要手改.`（英文环境为 `// Generated by Jotl. Do not edit.`）开头，声明 `export interface Home`，其中有 `title: string`。去掉 `--to ts` 则输出 JSON Schema。

## 能做什么

- **Jotl、JSON Schema 2020-12 与 TS 声明之间任意互转。** `compile` 与 `convert` 输出到 stdout 或 `--out`；`--typia-tags` 让 TS 输出带 typia 类型标签。
- 在 CI 里拦下坏数据和坏 schema：`validate` 把每个错误定位到数据文件里，`check` 只报告 schema 的问题、不输出结果，`defaults` 打印 schema 隐含的默认数据。
- 把旧 schema 升上来：`migrate-schema` 把 draft-04 至 2019-09、OpenAPI 3.0 / 3.1 与 Swagger 2.0 的 Schema Object 升级到 2020-12，并把 fengdie DSL schema 转成 Jotl。
- 输出便于脚本解析：一条诊断一行，退出码固定，`-` 从 stdin 读入，用 `--lang` 或 `JOTL_LANG` 选择中文或英文输出。
- 用上项目自己的组件：编译 Jotl 的命令会读取最近的 `jotl.config.json`，与编辑器读的是同一个文件。

## 适用边界

`jotl` 只读 Jotl、JSON Schema 与 TS 文件，只校验 JSON 数据。要在编辑时实时检查和预览 Jotl，用 [VS Code 插件](../../vscode/zh/README.md)，或把[语言服务](../../language-server/zh/README.md)接进你的编辑器；要在应用内校验数据，直接调用 [`@jotl/data`](../../data/zh/README.md)，不要另起命令行进程。
