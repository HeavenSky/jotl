# 在代码中调用语言服务

[English](../../docs/api.md) · **简体中文**

读完本页，你能把每项语言能力当普通函数调用，比如用在网页编辑器、lint 工具或测试里，不需要 LSP 连接。前提是已按[快速开始](../README.md)装好本包。

## 对一段文本调用某项能力

每个函数都接收文档文本、URI，需要时再加 LSP 位置或范围：

```js
import { getCodeActions, getDiagnostics, getHover, getPreview } from '@jotl/language-server';

const uri = 'file:///home.jotl';

const source = 'title: string\n';
const [diagnostic] = getDiagnostics(source, uri); // JOTL1036：顶层只能声明类型
getCodeActions(source, uri, diagnostic.range);
// [{ title: "Wrap in `Root: {...}` and mark `<root/>`", kind: "quickfix", isPreferred: true, edit: ... }]

getHover('Home: {\n  title: string[maxLength: 20]\n}\n', uri, { line: 1, character: 3 });
// contents：Markdown "Field `title`"，后接 JSON 片段 { "type": "string", "maxLength": 20 }

getPreview('Home: { title: string }', uri);
// { schema: JSON 文本, typescript: "// Generated by Jotl. Do not edit.\n\nexport interface Home {...", diagnostics: [], ... }
```

- 位置与范围遵循 LSP：行列从 0 起，列按 UTF-16 代码单元计。编译器的位置从 1 起，已在内部换算。
- `getPreview` 例外：其中的 `PreviewDiagnostic` 行列仍从 1 起，见[展示预览](editor-integration.md#展示预览)。
- 文字按 `@jotl/core` 的全局语言输出，默认英文；先调用 `setLocale("zh-CN")` 则为中文（上例注释中的输出均为英文环境）。

## 函数

| 函数                                                     | 返回               | 行为                                                                                                                                                                                      |
| -------------------------------------------------------- | ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `getDiagnostics(text, uri, options?)`                    | `Diagnostic[]`     | 编译器诊断加 widget 未注册检查（`JOTL7001`），按位置排序；`source` 为 `"jotl"`                                                                                                            |
| `getCodeActions(text, uri, range, options?)`             | `CodeAction[]`     | 与 `range` 相交的诊断上附带的全部修复；某条诊断只有一个修复时标为首选                                                                                                                     |
| `getCompletions(text, position, options?)`               | `CompletionItem[]` | 按光标处语境补全，见下文                                                                                                                                                                  |
| `getHover(text, uri, position, options?)`                | `Hover \| null`    | 类型名、类型引用与字段键显示编译后的 JSON 片段，超过 `MAX_FRAGMENT_LINES`（60）行时截断；内置组件、扩展组件（含底层 schema，文件根 `widgets` 元数据中的声明优先）、元数据键与标记显示说明 |
| `getDefinition(text, uri, position)`                     | `Location[]`       | 光标在顶层类型的引用（组件位置或类型串中）或声明名上时，返回其声明                                                                                                                        |
| `getReferences(text, uri, position, includeDeclaration)` | `Location[]`       | 本文件内对该顶层类型的引用                                                                                                                                                                |
| `getDocumentSymbols(text, uri)`                          | `DocumentSymbol[]` | 大纲：每个顶层类型一项，字段、分支与枚举成员逐层嵌套                                                                                                                                      |
| `getPreview(text, uri, options?, config?)`               | `PreviewContent`   | 编译出的 schema 与 TS 及各自的诊断；`config`（`{ file, modules }`）原样带到 `configFile` 与 `modules`。TS 以编译结果的 `defaultExport` 作默认导出                                         |

`getCompletions` 按光标位置给出：

- 组件位置：内置组件、本文件声明的类型、扩展组件（含根元数据 `widgets` 声明的名字）。
- 元数据 `[...]` 内：适用于该组件的键（`META_KEY_TARGETS`）。
- 取值：`widget`（按组件数据形态给出 `acceptsWidget` 接受的内置 widget，默认的排在首位，再接已登记名）、`decorator`、`value_format`（按日期组件给常用格式、时间戳与 4 个别名）和条件 `op`。
- 类型串中的名字，以及标记 `<root/>` 与 `<default/>`。

## 选项

`options` 为 `LanguageServiceOptions`：

| 字段                | 含义                                                                                                |
| ------------------- | --------------------------------------------------------------------------------------------------- |
| `registeredWidgets` | 已登记的 widget 名；默认为空，即只认 `@jotl/form/core` 的 `BUILTIN_WIDGETS`。大驼峰名同时是扩展组件 |
| `widgets`           | 已登记名字的底层 schema；不在其中的扩展组件按 `string` 编译                                         |

这些函数不读 `jotl.config.json`。要应用配置，用 `@jotl/core` 的 `readJotlConfig` 读取，再用 `withConfigWidgets(options, widgets)` 并入 `config.widgets`；同名时以配置为准，`options` 中已有的名字保留。

从客户端消息构造选项的辅助函数：

- `readInitializationOptions(raw)` 从 `initializationOptions` 或 `jotl` 设置节读出 `registeredWidgets`。
- `readLocaleOption(raw)` 从同样的对象读出 `locale`；没有或不是非空字符串时返回 `undefined`。

## 给 JSON 编辑用的 schema

- `createXUiJsonSchema()`：JSON Schema 文件中 `x-ui` 的 schema，`$id` 为 `X_UI_JSON_SCHEMA_ID`。VS Code 插件打包时把它写成 `x-ui.schema.json`。
- `createJotlConfigJsonSchema()` 与 `JOTL_CONFIG_FILE`：转出自 `@jotl/core`，分别是 `jotl.config.json` 的 schema 与文件名。VS Code 插件打包时把该 schema 写成 `jotl.config.schema.json`。

诊断代码见[接入编辑器](editor-integration.md#诊断代码)；代码表以 `LSP_DIAGNOSTICS` 导出。
