# @jotl/language-server

[English](./README.md) · **简体中文**

把 Jotl 语言服务接入编辑器(LSP 客户端), 或在代码中直接调用诊断, 补全, 悬停, 跳转与预览函数时读本页; 对应 `packages/language-server`.

`@jotl/language-server` 为 `.jotl` 源码提供实时诊断与快速修复, 补全, 悬停, 跳转定义与查找引用, 大纲, 以及预览内容(编译出的 JSON Schema 与 TS 声明); 另生成一份给 JSON 语言服务用的 schema, 让 `*.schema.json` 中的 `x-ui` 有补全与校验.
各能力都是与连接无关的纯函数, `createServer` 把它们接到一个 LSP 连接上.
VS Code 插件(`packages/vscode`)是它的使用方, 手工验证步骤见 `packages/vscode/VERIFY.md`.

## 安装

```sh
pnpm add @jotl/language-server
```

## 启动服务

语言服务进程的入口只需一行, `packages/vscode/src/server.ts` 即是如此:

```ts
import { startServer } from "@jotl/language-server";

startServer();
```

- `startServer()` 按进程参数 `--node-ipc` `--stdio` `--socket` 选择传输方式并开始监听, 返回连接. 已有连接时用 `createServer(connection, { diagnosticsDelay? })` 注册处理函数, 再由调用方 `connection.listen()`.
- 文档按增量同步保存在内存中; 打开时立即全量编译并推送诊断, 改动后按 `diagnosticsDelay`(默认 `DIAGNOSTICS_DELAY` 即 200 毫秒)防抖, 只按最后的文本推送一次; 关闭文档时取消待推送的诊断并推送空诊断. 补全, 悬停等请求总是使用最新文本.
- 客户端经 `initializationOptions` 传入 `{ registeredWidgets: string[] }`(项目自行注册的 widget 名), 不合法的项被忽略, 重复项去重. 之后收到 `workspace/didChangeConfiguration` 且 `settings` 含 `jotl` 节(`{ jotl: { registeredWidgets } }`)时整体替换该选项, 并立即重新诊断全部已打开的文档. 其中的大驼峰名同时作为扩展组件经 `compile` 的 `options.widgets` 传给编译器, 底层类型按 `{ type: "string" }`.
- 诊断, 悬停, 补全说明与预览文字的语言: 先取 `initializationOptions.locale`, 再取 `initialize` 的 `params.locale`, 都没有时为 `en`; 取值为语言标签, 以 `zh` 开头为中文, 其余为英文(`@jotl/core` 的 `resolveLocale`). `jotl` 设置节中的 `locale`(`{ jotl: { locale: "en" } }`)可在运行时切换, 切换后重新诊断全部已打开的文档. 该设置作用于整个进程(`@jotl/core` 的全局语言), 直接调用各函数时先调用 `setLocale`.
- 文件根条目元数据 `widgets` 声明的名字(见 `@jotl/core` 的 README)在本文件内视为已登记: 组件位置与 `widget` 取值的补全会给出它们, `JOTL7001` 不报; 其底层类型由编译器自行处理.
- 每个 `file:` 文档从所在目录向上查找最近的 `jotl.config.json`(到含 `.git` 的目录或文件系统根为止; 格式见 `docs/spec/jotl.md` 的「扩展组件」), 其中的名字并入 `registeredWidgets`, 底层类型传给编译器; 同名时以配置文件为准, 设置中的名字补充, 只在设置中的大驼峰名仍按 `string` 编译. 结果按目录缓存; 收到 `workspace/didChangeWatchedFiles` 且其中有 `jotl.config.json` 时清空缓存并重新诊断全部已打开的文档. 配置文件读不到, 不是合法 JSON 或有不合法的项时, 在文档开头报 `JOTL7002`(warning), 出错的项被忽略, 其余照常生效.
- 预览走自定义请求 `PREVIEW_REQUEST_METHOD`(`"jotl/preview"`), 参数 `{ textDocument: { uri } }`, 返回 `PreviewContent`, 其中 `configFile` `modules` 为文档所属 `jotl.config.json` 的路径与模块声明; 文档未打开时返回 `null`. 服务端处理完 `jotl.config.json` 变更(清空配置缓存)后发出无参数通知 `PREVIEW_CONFIG_CHANGED_METHOD`(`"jotl/configChanged"`); 客户端应在收到时重新请求预览, 不要自己监听该文件, 否则会读到旧配置.
- VS Code 插件以 IPC 方式启动打包后的 `server.cjs`, 并把设置 `jotl.registeredWidgets` 作为 `initializationOptions` 传入, 之后经 `synchronize.configurationSection` 同步 `jotl` 节的变更, 经 `synchronize.fileEvents` 监听 `**/jotl.config.json`, 接线见 `packages/vscode/src/index.ts`.

## 直接调用

```ts
import { getCodeActions, getDiagnostics, getPreview } from "@jotl/language-server";

const uri = "file:///demo.jotl";
const text = "A: {\n  name: strng\n  title: string[widget: 'headline']\n}\n";

getDiagnostics(text, uri);
// [JOTL1004 错误, range.start { line: 1, character: 8 }], [JOTL7001 警告: headline 未注册]
getDiagnostics(text, uri, { registeredWidgets: ["headline"] });
// 只剩 JOTL1004

const source = "title: string\n";
const [diagnostic] = getDiagnostics(source, uri); // JOTL1036: 顶层只能声明类型
getCodeActions(source, uri, diagnostic!.range); // [{ title: "包进 `Root(根): {...}` 并标 `<root/>`", kind: "quickfix", ... }]

getPreview("R: { a: string }", uri);
// { schema: 两空格缩进的 JSON 文本, typescript: 以 "// 由 Jotl 生成, 不要手改." 开头(en 下为 "// Generated by Jotl. Do not edit."), diagnostics: [] }
```

- 位置与范围是 LSP 约定: 行列从 0 起, 列按 UTF-16 代码单元计; 编译器诊断的行列从 1 起, 已在此换算.
- `getPreview` 返回的 `PreviewDiagnostic` 行列仍从 1 起, TS 转换的诊断经编译产物的源码映射换算回源码位置, 换算不到时只有 `pointer`.

## 公开 API

| 导出 | 返回 | 说明 |
|---|---|---|
| `getDiagnostics(text, uri, options?)` | LSP `Diagnostic[]` | 编译器诊断加 widget 未注册检查, 按位置排序; `source` 为 `"jotl"` |
| `getCodeActions(text, uri, range, options?)` | `CodeAction[]` | 与 `range` 相交的诊断上附带的全部修复; 只有一个修复时标为首选 |
| `getCompletions(text, position, options?)` | `CompletionItem[]` | 按光标处语境补全: 组件位置给内置组件, 本文件类型与扩展组件(含根元数据 `widgets` 声明的名字); 元数据 `[...]` 中给适用于该组件的键(`META_KEY_TARGETS`); `widget` 取值(按组件的数据形态给出编译器 `acceptsWidget` 接受的内置 widget, 首个为默认, 再接已登记名), `decorator` 取值, `value_format` 取值(按日期组件给常用格式, 时间戳与 4 个别名), 条件 `op`, 类型串中的名字, `<root/>` `<default/>`; 触发字符见 `COMPLETION_TRIGGER_CHARACTERS` |
| `getHover(text, uri, position, options?)` | `Hover \| null` | 类型名, 类型引用与字段键显示编译后的 JSON 片段, 超过 `MAX_FRAGMENT_LINES` 行时截断; 内置组件, 扩展组件(含底层 schema, 文件根 `widgets` 的声明优先), 元数据键与标识记号显示说明 |
| `getDefinition(text, uri, position)` | `Location[]` | 光标在顶层类型的引用(组件位置或类型串中)或声明名上时返回其声明 |
| `getReferences(text, uri, position, includeDeclaration)` | `Location[]` | 本文件内对该顶层类型的引用 |
| `getDocumentSymbols(text, uri)` | `DocumentSymbol[]` | 大纲: 每个顶层类型一项, 字段, 分支与枚举成员逐层嵌套 |
| `getPreview(text, uri, options?, config?)` | `PreviewContent` | 有 error 级诊断时 `schema` 与 `typescript` 为 `undefined`; TS 按编译结果的 `defaultExport` 默认导出; `config`(`{ file, modules }`)原样带到 `configFile` 与 `modules`, `module` 中的相对路径按 `configFile` 所在目录解析 |
| `readInitializationOptions(raw)` | `LanguageServiceOptions` | 从 `initializationOptions` 读出选项 |
| `readLocaleOption(raw)` | `string \| undefined` | 从 `initializationOptions` 或 `jotl` 设置节读出 `locale`; 没有或不是非空字符串时为 `undefined` |
| `withConfigWidgets(options, widgets)` | `LanguageServiceOptions` | 并入 `jotl.config.json` 的登记(`readJotlConfig` 的 `config.widgets`), 规则同上文 |
| `createJotlConfigJsonSchema()` `JOTL_CONFIG_FILE` | `JsonSchemaObject`, `string` | 转出自 `@jotl/core`; 插件打包时写成 `jotl.config.schema.json` |
| `createXUiJsonSchema()` | `JsonSchemaObject` | `$id` 为 `X_UI_JSON_SCHEMA_ID` 的 JSON Schema, 沿 2020-12 的全部子 schema 关键字递归, 在每个节点上按 `xUiMetaSchema` 校验 `x-ui`; 插件打包时写成 `x-ui.schema.json` |
| `createServer(connection, options?)` `startServer()` | `void`, `Connection` | 见上文 "启动服务" |

`options` 为 `LanguageServiceOptions`: `registeredWidgets` 默认为空, 即只认 `@jotl/form/core` 的 `BUILTIN_WIDGETS`, 也没有扩展组件; `widgets` 为已登记名字的底层 schema, 不在其中的扩展组件按 `string` 编译. 直接调用这些函数时不查找 `jotl.config.json`, 需要时由调用方读取后用 `withConfigWidgets` 并入.

## 诊断代码

- 本包自己的诊断为 `JOTL7xxx`, 代码表见 `src/diagnostics.ts` 的 `LSP_DIAGNOSTICS`; 其中 `JOTL7001` 表示元数据 `widget` `decorator` 引用的 widget 名(含 `variants` 各场景覆盖中的 `widget` `decorator`)既不是内置 widget, 也不在 `registeredWidgets` 中, 也不是文件根元数据 `widgets` 声明的名字, 渲染时将降级(warning); `JOTL7002` 表示文档所属的 `jotl.config.json` 有误(warning, 报在文档开头).
- 其余诊断原样来自 `@jotl/core` 的编译器(`JOTL1xxx`); 预览中的 TS 转换诊断来自 `@jotl/convert`(`JOTL2xxx`).
