Language support for [Jotl](https://github.com/jotl-lang/jotl) `.jotl` files, with a live preview of the compiled JSON Schema, TypeScript declarations and form.

> This is a preview release; behavior and settings may still change.

## Features

- **Syntax highlighting** for `.jotl` files.
- **Diagnostics while you type**, with quick fixes.
- **Completion** for widget names, metadata keys, `widget` values, condition `op` values and the `<root/>` / `<default/>` markers.
- **Hover** with descriptions and the compiled snippet for the field under the cursor.
- **Go to Definition** and **Find All References** for top-level types, plus an **outline** of the document.
- **Preview panel** (`Jotl: Open Preview`, also on the editor title bar) with three tabs; code is syntax-highlighted and the panel, including the form, follows the current color theme (light, dark or high contrast):
  - **JSON Schema** — the compiled schema and its diagnostics;
  - **TS** — the generated TypeScript declarations and conversion diagnostics;
  - **Form** — a form rendered from the schema. It is for preview only; changes are not written back to the file. Extension widget modules can be loaded into it (see [Extension widget modules](#extension-widget-modules)).
- **`x-ui` validation in JSON Schema files**: `*.schema.json` files get completion and validation for `x-ui` definitions. This does not work when the file has a root `$schema`: VS Code's JSON language service then loads only the schema at that address and ignores schemas associated by file name. If needed, remove the root `$schema` while editing `x-ui` and add it back afterwards (schemas generated by Jotl always include it), or edit the `.jotl` source instead.
- **Project configuration**: widgets declared in `jotl.config.json` are picked up per file (see below).

## Commands

| Command | Description |
| --- | --- |
| `Jotl: Open Preview` | Opens the preview beside the active `.jotl` editor; it follows edits and editor switches. |

## Settings

| Setting | Default | Description |
| --- | --- | --- |
| `jotl.registeredWidgets` | `[]` | Widget names registered by your project in addition to the built-in ones, for example `["headline", "tag-list", "ImagePicker"]`. They appear in `widget: '` completions and are no longer reported as unregistered widgets (`JOTL7001`). PascalCase names can also be used as extension widgets in the widget position (compiled as `string`). |
| `jotl.preview.loadWidgetModules` | `false` | Load extension widget modules in the preview form (see [Extension widget modules](#extension-widget-modules)). When off, those widgets use the fallback display and the preview shows a notice. In untrusted workspaces the workspace value is ignored, so a repository cannot turn it on by itself. |

Changes to the settings take effect immediately: the language server re-checks open files and the preview reloads without reloading the window.

## Project configuration

Put a `jotl.config.json` in your project to register widgets together with their underlying types; each `.jotl` file uses the nearest one found in its folder or a parent folder (stopping at the Git root):

```json
{ "widgets": { "ImagePicker": "url", "tag-list": "array", "headline": "string" } }
```

A type is a JSON Schema type name, a Jotl built-in widget name without a body, or a schema object. The file takes precedence over `jotl.registeredWidgets`, which only adds names. Edits to the file re-check open files immediately; problems in it are reported at the top of each affected `.jotl` file (`JOTL7002`). The file itself gets completion and validation. The `jotl` command line reads the same file.

## Extension widget modules

A widget can point to a React component module, either in `jotl.config.json` or in the `widgets` metadata of a file's root entry (the file's declaration wins over the config):

```json
{ "widgets": { "ImagePicker": { "base": "url", "module": "https://esm.sh/my-image-picker?external=react,react-dom", "export": "default" } } }
```

```jotl
Page: [widgets: {ImagePicker: {base: 'url', module: './widgets/image-picker.js'}}] {
  cover: ImagePicker
}
```

The compiled schema keeps root-entry modules in the root `x-ui.widgets`. The preview does not run them by default; turn on `jotl.preview.loadWidgetModules` to load them:

- `module` is an `https:` URL or a path relative to the declaring file (`./`, `../`, or an absolute path); local files are served to the preview from the workspace.
- A module must be an ES module whose export (`export`, default `default`) is a React component following the `@jotl/form` widget contract.
- The preview shares its own React with modules: bare imports of `react`, `react/jsx-runtime`, `react-dom` and `react-dom/client` resolve to the preview's copy. Do not bundle React into the module (with esm.sh, add `?external=react,react-dom`).
- A module that fails to load shows an error with a retry button in its field; the rest of the form keeps working.

## Language

The extension follows the VS Code display language: command titles, settings, the preview panel and its form, and the diagnostics, hovers and completions from the Jotl language server. English and Simplified Chinese are included; Chinese display languages use Simplified Chinese and all others use English. After changing the display language, restart VS Code as usual.

## Requirements

VS Code 1.101 or later. No other installation is needed: the language server is bundled with the extension.
