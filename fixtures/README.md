# Shared fixtures

**English** · [简体中文](./zh/README.md)

The samples in `fixtures/` are the expected values that every package's tests compare against, so changing an existing sample changes the contract and every package has to follow. This page describes the sample layout, the comparison rules and the expected-output conventions; tests read the samples through `test-utils/fixtures.ts`. Syntax and contracts follow the [Jotl spec](../docs/spec/jotl.md) and the [x-ui spec](../docs/spec/x-ui.md).

## Layout

```
fixtures/
  <three-digit number>-<short English name>/
    source.jotl          Jotl source
    schema.json          expected compilation result (normalized JSON Schema 2020-12)
    types.d.ts           expected TS output
    defaults.json        expected default data (strategy explicit, other options at defaults)
    valid/*.json         data that should pass validation
    invalid/*.json       data that should fail; the same-named *.errors.json holds the expected errors
    diagnostics.json     only present in samples expected to fail compilation; the expected diagnostics
    meta.json            { "covers": [feature item numbers], "skip": [skipped expectation files], "defaultExport": default export type name }
```

Each new sample takes a number from its package's range: `1xx` core (syntax), `2xx` convert (TS), `4xx` data, `5xx` form (core/), `7xx` form (html/); `001`-`099` are the shared base samples.

## Comparison rules

| File | Comparison |
|---|---|
| `schema.json` | Deep equality, keyword order not compared |
| `types.d.ts` | Exact equality after normalizing to LF |
| `defaults.json` | Deep equality |
| `*.errors.json` | Set equality on `{ code, pointer }`, order and message text not compared |
| `diagnostics.json` | Set equality on `{ code, line, column }`; lines and columns start at 1, and columns count UTF-16 code units |

## Expected error conventions

- `pointer` is a JSON Pointer into the data. For a missing required field it points to the missing field itself (e.g. `/name`), and for a disallowed field (`JOTL4008`) to the extra field itself (e.g. `/zip`); neither points to the parent object.
- One violation produces one error: a mismatched labeled enum (`const` branches of `oneOf`) reports only `JOTL4006`, without the errors of each branch; when every `anyOf` branch fails, only `JOTL4012` is reported; after a type mismatch, no other constraint on the same node is reported.
- The meaning of each code is defined in `packages/data/src/diagnostics.ts`.
- The `color` format is a CSS hexadecimal color: `#rgb` `#rgba` `#rrggbb` `#rrggbbaa`.

## TS output format

`types.d.ts` is generated from the schema; the JSDoc tags are defined in the [`@jotl/convert` tag protocol](../packages/convert/docs/tag-protocol.md). The format follows these conventions:

- The first line is `// 由 Jotl 生成, 不要手改.` (the Chinese generated header, "Generated by Jotl. Do not edit."), followed by a blank line; top-level declarations are separated by a blank line; the file ends with a newline.
- All types in `$defs` are exported, in `$defs` order; objects are `export interface`, everything else `export type`. The file ends with `export default X;`, where X is the source's default export (`<default/>`) or, if there is none, the type the root `$ref` points to.
- When the default export differs from the root (only in samples with `meta.defaultExport`), `types.d.ts` is generated under that name and the root type's comment gets `@root`. `meta.defaultExport` must equal the `defaultExport` compiled from `source.jotl`; core's syntax sample tests check this, and packages that do not compile the source (`@jotl/convert`) read it from `meta.json`.
- Two-space indentation; inline objects and index signatures are expanded to multiple lines; property order follows the schema.
- A node with a description or tags gets a multi-line JSDoc: description lines first, then tags in normalized keyword order. `type: integer` becomes `@asType integer`, except when the node is an enum or a const.
- When array elements are enums, `@enumTitles` goes on the array property; the elements' `x-ui` becomes `@itemWidget` / `@itemUi` on the array property.
- In a discriminated union, branches referenced via `allOf` become intersection types `X & { kind: "x" }`, and the branch `title`s become `@branchTitles` on the union node.
- When `x-ui` has only `widget`, write `@widget name`; otherwise write ``@ui `{...}` ``.
- The root `$id` and root `x-ui.rules` go at the end of the root type's comment: `@id URI`, ``@rules `[...]` ``; when `@root` is present it comes before both.

When a sample contains something `@jotl/convert` cannot express, which it drops with `JOTL2002`, the sample skips `types.d.ts` through `meta.skip`:

- Element-level constraints or annotations: constraints, `title` and `x-ui` on array elements, `map` values, union branches and tuple positions (except `x-ui` on array elements): `007` `109` `110`.
- `additionalProperties: false` (`closed`; not reported on `money` `bigint` value objects): `101` `109`.
- The Jotl extension keyword `x-decimals` (other than on `money` `bigint`) and `contentSchema` `propertyNames`: `108` `110`.
