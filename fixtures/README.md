# Shared fixtures

**English** · [简体中文](./README.zh-CN.md)

Read this page when adding or modifying samples, or when implementing a package's comparison against samples; it corresponds to `fixtures/` and the reader utility `test-utils/fixtures.ts`.

Samples are the shared expected values of every package's tests; syntax and contracts follow `docs/spec/` (Chinese). Modifying an existing sample is equivalent to modifying the contract, and every package must follow suit.

## Layout

```
fixtures/
  <three-digit number>-<short English name>/
    source.jotl          Jotl source
    schema.json          expected compilation result (normalized JSON Schema 2020-12)
    types.d.ts           expected TS output
    defaults.json        expected default data (strategy explicit, other options at defaults)
    valid/*.json         data that should pass validation
    invalid/*.json       data that should fail; the same-named *.errors.json holds the expected errors
    diagnostics.json     only present in samples expected to fail compilation; the expected diagnostics
    meta.json            { "covers": [feature item numbers], "skip": [skipped expectation files], "defaultExport": default export type name }
```

New samples belong to number ranges: `1xx` core (syntax), `2xx` convert (TS), `4xx` data, `5xx` form (core/), `7xx` form (html/); `001`-`099` are shared base samples.

## Comparison rules

| File | Comparison |
|---|---|
| `schema.json` | Deep equality, keyword order not compared |
| `types.d.ts` | Exact equality after normalizing to LF |
| `defaults.json` | Deep equality |
| `*.errors.json` | Set equality on `{ code, pointer }`, order and message text not compared |
| `diagnostics.json` | Set equality on `{ code, line, column }`; lines and columns start at 1, columns count UTF-16 code units |

## Expected error conventions

- `pointer` is a JSON Pointer into the data. A missing required field points to the missing field itself (e.g. `/name`), and a disallowed field (`JOTL4008`) points to the extra field itself (e.g. `/zip`); neither points to the parent object.
- One violation reports only one error: a labeled enum (`const` branches of `oneOf`) mismatch reports only `JOTL4006` without expanding each branch's errors; when all `anyOf` branches fail only `JOTL4012` is reported; on a type mismatch no other constraints on the same node are reported.
- For code meanings see `packages/data/src/diagnostics.ts`.
- The `color` format is a CSS hexadecimal color: `#rgb` `#rgba` `#rrggbb` `#rrggbbaa`.

## TS output format

`types.d.ts` is generated from the schema; for the tag system see the `@jotl/convert` documentation. Format conventions:

- The first line is `// 由 Jotl 生成, 不要手改.` ("Generated by Jotl, do not edit by hand."), followed by a blank line; top-level declarations are separated by a blank line; the file ends with a newline.
- All types in `$defs` are exported, in `$defs` order; objects are `export interface`, everything else `export type`. At the end write `export default X;`: X is the source's default export (`<default/>`), or, when not written, the type the root `$ref` points to.
- When the default export differs from the root (only samples with `meta.defaultExport`), `types.d.ts` is generated under that name and the root type's comment gets `@root`; `meta.defaultExport` must equal the `defaultExport` compiled from source.jotl, checked by core's syntax sample tests, for use by packages that do not compile the source (`@jotl/convert`).
- Two-space indentation; inline objects and index signatures are expanded to multiple lines; property order follows the schema.
- When there is a description or tags, write a multi-line JSDoc: description lines first, then tags in normalized keyword order. `type: integer` is written as `@asType integer`, omitted when the node is an enum or const.
- When array elements are enums, `@enumTitles` goes on the array property; the elements' `x-ui` is written as `@itemWidget` / `@itemUi` on the array property.
- In a discriminated union, branches referenced via `allOf` are written as intersection types `X & { kind: "x" }`, and branch `title`s are written as `@branchTitles` on the union node.
- When `x-ui` has only `widget`, write `@widget name`, otherwise ``@ui `{...}` ``.
- The root `$id` and root `x-ui.rules` go at the end of the root type's comment: `@id URI`, ``@rules `[...]` ``; when `@root` is present it comes before both.

When content appears that `@jotl/convert` cannot express and therefore drops with `JOTL2002`, the sample skips `types.d.ts` via `meta.skip`:

- Element-level constraints or annotations: constraints, `title` and `x-ui` on array elements, `map` values, union branches and tuple positions (except `x-ui` on array elements): `007` `109` `110`.
- `additionalProperties: false` (`closed`; not reported on `money` `bigint` value objects): `101` `109`.
- The Jotl extension keyword `x-decimals` (other than on `money` `bigint`) and `contentSchema` `propertyNames`: `108` `110`.
