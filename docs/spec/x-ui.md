# x-ui Specification v1 and Widget Contract

**English** · [简体中文](../../zh/docs/spec/x-ui.md)

This page defines how to write `x-ui` in a schema, how widgets are selected and fall back, and the contract a widget package must implement.

`x-ui` is the only extension keyword on a schema node. You can put it on any node or leave it out entirely; without it, widgets are chosen automatically by built-in rules.
The type is `XUi` in `@jotl/core` ([`packages/core/src/schema/x-ui.ts`](../../packages/core/src/schema/x-ui.ts)) and the widget contract lives in `@jotl/form/core` ([`packages/form/src/core/contracts.ts`](../../packages/form/src/core/contracts.ts)); neither depends on a UI framework.

## Fields

| Field       | Value                                          | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ----------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `widget`    | Non-empty string                               | Widget name; for built-in names see [Built-in widget names](#built-in-widget-names)                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `props`     | Object                                         | Parameters passed through to the widget; must be JSON-serializable                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `decorator` | Non-empty string or `false`                    | Widget name of the field wrapper; `false` means no wrapper                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `order`     | Array of strings                               | Object nodes: order of child fields; fields not listed follow in their original order                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `groups`    | `{ title, fields }[]`                          | Object nodes: field groups; ungrouped fields come first                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `layout`    | `"stack"` `"tabs"` `"grid"`                    | Layout of an object node, default `stack`; with `tabs`, each `groups` entry gets a tab and ungrouped fields go on the first tab                                                                                                                                                                                                                                                                                                                                                                                                 |
| `columns`   | Integer of at least 1                          | Number of columns when `layout` is `grid`, default 2                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `hidden`    | Boolean                                        | Hides the node                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `visibleIf` | [Visibility condition](#visibility-conditions) | The node is not shown while the condition is false                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `summary`   | Field name                                     | Objects, arrays of objects and maps: entry rows and breadcrumbs show this field's value; see [Drill-down rendering](#drill-down-rendering)                                                                                                                                                                                                                                                                                                                                                                                      |
| `thousands` | Boolean                                        | `number` `integer` `money` `bigint`: show thousands separators when not focused and when read-only; defaults to `true` for `money`, `false` otherwise                                                                                                                                                                                                                                                                                                                                                                           |
| `variants`  | Scene name → scene override object             | Overrides per rendering scene; the scene name is passed in by the renderer, default `"default"`                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `rules`     | Array of [rules](#rule-table)                  | Only takes effect on the root node                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `version`   | `1`                                            | Only appears on the root node                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `widgets`   | Widget name → `{ base?, module, export? }`     | Only appears on the root node: the ES module URL implementing the widget and its export name (default `default`). `base` is the underlying type of the extension component (a type name or a schema object, default `object`, present only when another underlying type is declared); `print` and editors use it to restore the extension component, and renderers ignore it. This field is compiled from the module declarations in the `widgets` metadata of the Jotl root entry, and renderers can use it to load components |

A scene override object and a rule's `ui` may contain only `widget` `props` `decorator` `order` `groups` `layout` `columns` `hidden` `visibleIf` `summary` `thousands`; they must not contain `variants` `rules` `version` `widgets`.

## Visibility conditions

```ts
type Leaf = { field: JsonPointer; base?: 'node' };
type Condition =
  | (Leaf & ({ eq: unknown } | { ne: unknown } | { in: unknown[] } | { notIn: unknown[] } | { truthy: boolean }))
  | (Leaf & ({ gt: number } | { gte: number } | { lt: number } | { lte: number }))
  | { all: Condition[] }
  | { any: Condition[] }
  | { not: Condition };
```

- A leaf condition consists of `field`, an optional `base` and exactly one comparison.
- `field` is a JSON Pointer. Without `base` it starts at the data root; with `base: "node"` it starts at the object containing the current node. A `*` in it takes the corresponding index of the array containing the current node.
- `gt` `gte` `lt` `lte` compare only when both sides are numbers; otherwise they are false.
- Comparison uses deep equality of JSON values. When the value `field` points to does not exist, `eq` `in` `truthy: true` are false and `ne` `notIn` `truthy: false` are true. `truthy` follows JavaScript truthiness, so an empty array is truthy.
- Invisible fields keep their data and are still validated; their errors appear in the form-level error list (`ViewProps.errors`).
- The evaluator is `evaluateCondition(cond, data, dataPath)` from `@jotl/form/core`, where `dataPath` is the actual path of the current node.

## Rule table

```ts
interface UiRule {
  match: { pointer?: string; type?: string; format?: string; enum?: boolean; widget?: string };
  ui: XUiVariant;
}
```

- A rule matches only when every condition in `match` holds.
- `pointer` matches a pointer inside the schema document; `*` matches a single segment.
- `type` requires the node's `type` to be exactly that single type (`["string", "null"]` does not match `"string"`); `format` matches the node's keyword of the same name; `enum: true` matches enum nodes and `enum: false` matches non-enum nodes.
- A rule with `pointer` never matches nodes synthesized by splitting a `type` array, since they share the pointer of the node they were split from.
- `widget` matches the widget name chosen for the node without the rule layer.
- When several rules match, they are merged in array order, and later ones override earlier ones.

## Merge order

A node's effective `x-ui` is merged from the following layers in order, each overriding the previous one:

1. Matching entries of the root `rules`
2. `x-ui` on the referenced type (`$defs`)
3. `x-ui` on the node itself or at the reference site (next to `$ref`)
4. `variants[scene]` for the current scene

- Objects are merged shallowly, and `props` gets one more level of shallow merging.
- `layout`, `columns`, `visibleIf` and the like take their merged values and are written into the render plan node.

## Widget name candidates and fallback chain

`widget` is not overridden by shallow merging: the `widget` from each layer of the merge order goes into a candidate list, highest priority first.

Candidate order (highest priority first): scene variant at the node → scene variant of the referenced type → the node itself or the reference site → the referenced type → the root rule table (later rules in the array come first). Duplicate names keep only the earliest candidate, and a scene variant counts as coming from the layer it sits in.

- The candidate list is followed by registry matchers (registrations whose `match` returns a value greater than 0, higher scores first), then the built-in matching rules, and finally the fallback widget `json`.
- `plan()` takes the first usable candidate in order: an unregistered widget name records F1 and moves on; a built-in name that does not accept the data shape (see `builtinAccepts` below), or a registration whose `accepts` rejects it, records F2 and moves on.
- When the schema uses a feature the renderer does not support (`JOTL5004`), or the node's `$ref` cannot be resolved (`JOTL5005`), the node uses `json` and records F7.
- Candidates after the selected widget that are still usable (registered and passing the shape check) go into `RenderPlanNode.fallbackChain`, ending with `json`; it is empty when the selected widget is `json` itself. When a widget throws during rendering (F4), replacements are taken from this chain in order.
- When the selected widget is in the `view`, `layout` or `composite` level and its registration has `claims(schema)`, child nodes at the relative data paths it returns (such as `"img"`) stay out of the render plan; the widget renders them itself, and they are planned on demand when handed back through `renderChild`. Returning `"all"` plans no child nodes at all.
- `RenderPlanNode.source` records where the selected widget came from: `node` the node itself or the reference site, `ref` the referenced type, `rule` the root rule table, `matcher` a registry matcher, `builtin` the built-in matching rules, `fallback` the fallback.
- On a nullable node (`T | null`), a built-in non-`nullable` widget name in `x-ui.widget`, together with `thousands` and `summary`, describes the content: it is carried to the non-null branch and is neither a candidate for the nullable node itself nor recorded as F2. The rest of `x-ui` (such as `hidden`) applies to the nullable node.

## Invalid x-ui

When a node's `x-ui` does not conform to the meta-schema, the node is treated as having no `x-ui` and F3 is recorded in `degraded`; other nodes are unaffected.

The meta-schema is `xUiMetaSchema` exported by `@jotl/core` ([`packages/core/src/schema/x-ui-meta-schema.ts`](../../packages/core/src/schema/x-ui-meta-schema.ts)) with `$id` `https://jotl.dev/schema/x-ui/v1`; validation and editor completion use it. `@jotl/form/core` does not depend on Ajv and decides F3 with `checkXUi`, a hand-written structural check following the same rules. When the root node's `x-ui` is invalid, the root rule table is discarded as well.
The meta-schema is stricter than the TS type: it rejects unknown fields, empty strings in `widget` `decorator` `summary`, `columns` that are not integers or are less than 1, and leaf conditions with more than one comparison.

- The mapping from `format` to widget name is `FORMAT_WIDGETS`.
- `@jotl/form/core` checks shapes for all built-in widget names in one place (`builtinAccepts`): when the built-in widget named by `widget` does not accept the shape, it is skipped as F2 and the next candidate is used, usually the default widget for the shape. Nothing is shown in the UI; the degradation is reported to developers through `onDegrade`.

## Drill-down rendering

`@jotl/form` drills down page by page by default; with `drill={false}` on `JotlForm`, all levels expand on the same page. Adding `collapsible` wraps each composite field expanded on the page (`page` objects, `list`, `kv`, `union` with object branches; except `inline` and `tree`) in a collapsible panel: the header shows the title (`Item n` for array elements), the summary (same rules as entry rows) and the number of errors below it. The first level is expanded by default and deeper levels are collapsed.

- One page per level: scalar fields on the current page are edited in place. Composite fields that are not the page root (`page` objects, `list`, `kv`, `tree`, `union` with object branches) appear as entry rows with a label, a summary, the number of errors below them and an open button. `inline` objects expand inside the parent page; nullable nodes are judged by their content.
- While drilling, every page has breadcrumbs at the top (the root page has a single level), and the title of the page's root object is no longer shown. Fields show their `title` or key, array elements show their summary or `Item n`, and map values show their key.
- The summary is the value of the field named by `x-ui.summary`. Without it, the first non-empty string field is used (first in schema property order, then in data key order). Failing that, a fill status is shown (`Empty`, `n items`, `n filled`). The list shows array element numbers itself; in breadcrumbs, an array element without a summary shows `Item n`.
- The current page path (a JSON Pointer) comes from the controlled props `path` / `onPathChange`; without them the form tracks it internally. When an array index in the path is out of range (the element was removed), or a map key in it no longer exists (removed or renamed), the form returns to the level of that array or map and notifies `onPathChange`; an invalid path returns to the root.
- When validation fails on submit, the form jumps to the deepest page on the path of the first error.
- Optional base styles for breadcrumbs and entry rows are in `@jotl/form/style.css`; breadcrumbs stay on one line and scroll horizontally when too wide.
- In a union discriminated by JSON type, branches without a `title` are shown in the dropdown by type name in the form's locale (in English: Text, Number, Integer, Yes/No, List, Object, and Empty for `null`).

## Widget props by level

`N` is the framework's node type, `React.ReactNode` for React. For the full types see [`packages/form/src/core/contracts.ts`](../../packages/form/src/core/contracts.ts).

| Interface           | Used by                                       | Contents beyond `BaseProps`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ------------------- | --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `BaseProps<N>`      | All levels except the wrapper                 | `id` a stable id, used for the label's `for` and `aria-describedby`; `schema`; `dataPath` the actual path, with concrete array indices; `mode`; `props` the merged `x-ui.props`; `adapters`; `renderChild(relativePath)`                                                                                                                                                                                                                                                                                                                                                       |
| `FieldProps<V, N>`  | field level                                   | `required` (whether it is a required field of its parent object; false for the root and array elements) `value` `onChange(value)` `onBlur()` `errors` `thousands`                                                                                                                                                                                                                                                                                                                                                                                                              |
| `DecoratorProps<N>` | decorator level (does not extend `BaseProps`) | `id` `label?` `description?` `required` `errors` `hidden` `children`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `LayoutProps<N>`    | `page` `inline`                               | `fields`: `{ key, required, hidden, errorCount? }[]`, already sorted by `order`; `hidden` already includes the result of evaluating `visibleIf`; `errorCount` is the number of errors currently shown on the field and its subpaths (absent when the renderer does not provide it); `groups`; `layout`; `columns`; `additional?`: provided when the object also has a schema-form `additionalProperties`, an `EntryEditing` for keys outside `properties` (the same as the entry-editing part of `MapProps`)                                                                   |
| `ArrayProps<N>`     | `list`                                        | `items`: `{ key, dataPath }[]`, where `key` is a stable element key that does not change with reordering; `canAdd` `canRemove` computed from `minItems` / `maxItems` and `mode`; `add(index?)` `remove(index)` `move(from, to)`; `duplicate?(index)` deep-copies the item and inserts the copy after it, subject to `canAdd`; when the renderer does not provide it, the widget shows no duplicate action; `errors` errors of the array itself (such as item count out of range)                                                                                               |
| `TupleProps<N>`     | `tuple`                                       | `items: { dataPath }[]`, the actual paths of the `prefixItems` positions; `errors` errors of the tuple itself; item i is rendered with `renderChild(String(i))`; `rest?` is provided only when `items` allows rest elements: `items: { key, index, dataPath }[]`, `canAdd` `canRemove` `add()` `remove(index)`, optional `move(from, to)` (both actual indexes of rest elements, otherwise nothing happens) and `duplicate(index)` (inserts a deep copy after it, subject to `canAdd`), and rest elements are rendered by their actual index with `renderChild(String(index))` |
| `UnionProps<N>`     | `union`                                       | `branches: { title }[]` `activeBranch` `selectBranch(index)` `renderContent()` (renders the current branch, with the same data path as this node) `errors`; the built-in `union` reads `props.selector`: with `"buttons"` and at most 4 branches, the branch is chosen with segmented buttons                                                                                                                                                                                                                                                                                  |
| `NullableProps<N>`  | `nullable`                                    | `isNull` `setNull(isNull)` `renderContent()` (renders the non-null branch when not null, with the same data path as this node) `errors`                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `MapProps<N>`       | `kv`                                          | `entries: { key, name, dataPath }[]`, where `key` is the entry's stable key and `name` is the map key; `canAdd` `canRemove`; `addEntry(name)` `removeEntry(name)` `renameEntry(from, to)`; `errors`                                                                                                                                                                                                                                                                                                                                                                            |
| `TreeProps<N>`      | `tree`                                        | `expanded` `setExpanded(expanded)` `renderContent()` `errors`; content is not rendered while collapsed                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `ViewProps<N>`      | `form`                                        | `submit()` `reset()` `children`; `errors`: errors that belong to no visible field (including those not on the current page while drilling); `goToError?(error)`: locates one entry of `errors`, switching to its page first while drilling, then scrolling to and focusing the field (or the nearest visible ancestor when the field is invisible); when the renderer does not provide it, the widget shows errors as plain text                                                                                                                                               |

- The argument of `renderChild(relativePath)` is a relative data path, such as `"img"`, `"0"` or `"0/img"`; the rendered child's own `x-ui` still applies.
- In the render plan, an object node that has both `properties` and a schema-form `additionalProperties` gets one more child after the property children: a value template for the remaining keys (data segment `*`, schema location `additionalProperties`). A tuple node has one child per `prefixItems` position, plus a rest element template at the end when `items` allows rest elements (data segment `*`, schema location `items`).
- `Adapters<N>` are pluggable external capabilities, each optional: `upload(file, ctx)` uploads and returns a URL, where `ctx` is an `UploadContext` (`dataPath` the actual path, `schema` the field's schema); `loadOptions(source)` returns remote options `{ value, label }[]`; `richText(props)` renders a rich text editor (you can pass `richTextEditor` from `@jotl/form` directly).
- Every widget is a stateless controlled widget: the value comes only from `value`, and changes go only through `onChange`.
- Apart from UI state that is not data (such as upload status or the selected tab), the only local state allowed is draft text that is not yet valid while typing (such as `-` in a number box or an unclosed bracket in the JSON editor); call `onChange` as soon as it becomes valid. The exception: `number` `money` `bigint` use focus state to switch between the raw value and the thousands-separated display.

## Fallback ownership

| Code        | Scenario                                                                                                         | Handled by                                                                                                                                                                                                              |
| ----------- | ---------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F1 F2 F3 F7 | Widget not registered, data shape not matched, invalid `x-ui`, unsupported schema feature or unresolvable `$ref` | `plan()`, recorded in `degraded`; exceptions: an unregistered wrapper widget name, and a registry without `json`, are handled by `@jotl/form` at render time as F1                                                      |
| F4          | Widget throws while rendering                                                                                    | The `@jotl/form` error boundary, replacing it from `fallbackChain` in order                                                                                                                                             |
| F5          | Composite widget throws                                                                                          | `@jotl/form`, which splits it up and renders each child node separately                                                                                                                                                 |
| F6          | Fallback widget `json`                                                                                           | The default widget implementation in `@jotl/form`; the renderer also carries a minimal fallback (a read-only `<pre>` in `view` mode, otherwise a JSON `<textarea>`) so the page is never blank without a widget package |
| F8          | Data does not match the schema                                                                                   | `@jotl/form`, which keeps the original value, marks an error and uses `json` for the node                                                                                                                               |
| F9          | Lazy loading fails                                                                                               | `@jotl/form`, which shows a load-failure message with a retry button and meanwhile renders the next widget from `fallbackChain`, as with F4                                                                             |
