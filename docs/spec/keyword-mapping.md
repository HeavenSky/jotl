# Jotl, JSON Schema and TSDoc Keyword Mapping

**English** · [简体中文](../../zh/docs/spec/keyword-mapping.md)

This page maps each standard JSON Schema keyword to how it is written in Jotl source, in the generated JSON Schema and in TS declarations. Use it to look up how to write a field, or to review whether the three stay in one-to-one correspondence. `packages/core` handles Jotl → JSON Schema, and `packages/convert` handles conversion between JSON Schema and TS.

This page lists only standard keywords and their counterparts in the three forms. For the fields of `x-ui` see the [x-ui specification](x-ui.md), for syntax details see the [Jotl syntax specification](jotl.md), and for how values are encoded on the TS side see the [`@jotl/convert` tag protocol](../../packages/convert/docs/tag-protocol.md).

## How the three forms relate

- **JSON Schema 2020-12** is the only data format: validation, default data and widget selection all read nothing else.
- **Jotl** is the source language for writing JSON Schema: `compile` generates the schema, and `print` turns a schema back into Jotl.
- **TS declarations** are generated by `schemaToTs` and read back by `tsToSchema`: whatever types can express is written as TS types, and the rest as doc comment tags.

TS tags fall into three groups by origin, marked with superscripts in the "TS / TSDoc" column below:

| Mark | Origin | Notes |
|---|---|---|
| (none) | Standard TSDoc tags | `@deprecated` `@defaultValue` `@example` `@privateRemarks` `@readonly`, recognized by every TSDoc tool |
| ᴾ | Jotl protocol tags | Declared in [`packages/convert/tsdoc.json`](../../packages/convert/tsdoc.json); constraint tags share the names of their JSON Schema keywords; without this preset, TSDoc tools report unknown tags |
| ᵀ | The TS type itself | No tag; expressed by how the type is written |

"—" means the form has no counterpart: when the Jotl column is "—", the keyword can only be written verbatim through the `schema: {...}` metadata; when the TS column is "—", `schemaToTs` does not emit it and reports a `JOTL2002` warning, except for the fixed-dialect `$schema`, which is dropped silently.

## Document structure

| JSON Schema | Meaning | Jotl | TS / TSDoc | Usage |
|---|---|---|---|---|
| `$schema` | Dialect URI | Always written as `https://json-schema.org/draft/2020-12/schema`; cannot be written by hand | — | Root only |
| `$id` | Base URI of the document | Root entry metadata `id: 'https://...'` | ᴾ `@id URI`, on the root type's comment | Serves as this document's address in cross-document references; root only |
| `$defs` | Table of named types | Each top-level entry `X(label): ...` | ᵀ `export interface X` / `export type X` | Root only (normalization rule 2) |
| `$ref` | Reference to another schema | Type name `X` in a type position, compiled to `#/$defs/X` | ᵀ Type name `X` | The root and the default export are decided by `<root/>` `<default/>`, see [File structure](jotl.md#file-structure); the default export maps to `export default X;`, and when it differs from the root, the root type's comment carries ᴾ `@root`; `tsToSchema` uses the declaration with `@root` as the root, or the default export when there is none |
| `$comment` | Note for maintainers, not used in validation | `comment: '...'` | `@privateRemarks text` | `@comment` is also accepted when reading |
| `$anchor` | Anchor | — | — | Supported by validation, default data and `#name` references; not written in Jotl syntax, passed through via the `schema` metadata |
| `$dynamicRef` `$dynamicAnchor` `$vocabulary` | Dynamic references and vocabularies | — | — | Only partially supported by Ajv; `$dynamicRef` also makes the node degrade to `json` |

## Metadata

| JSON Schema | Meaning | Jotl | TS / TSDoc | Usage |
|---|---|---|---|---|
| `title` | Short title, used as the field label in forms | Label after the key: `key(Title)` `X(Title)` | ᴾ `@title Title` | For labels of enum members see `oneOf` below |
| `description` | Descriptive text | `description: '...'` | Comment body | `@description` is also accepted when reading; TSDoc `@remarks` is ignored |
| `default` | Default value | `default: value` | `@defaultValue JSON` | Jotl checks at compile time that the default satisfies the constraints; `@default` is also accepted when reading |
| `examples` | Array of example values | `examples: [...]` | One `@example JSON` per example | Documentation only, not used in validation |
| `deprecated` | Deprecated | `deprecated: true` / `deprecated: 'reason'` | `@deprecated reason` | The reason goes into the extension keyword `x-deprecatedReason` |
| `readOnly` | Read-only, maintained by the server | `readOnly: true` | `@readonly` | `@readOnly` is also accepted when reading |
| `writeOnly` | Write-only, never echoed back | `writeOnly: true` | ᴾ `@writeOnly` | Such as passwords |

## Types and structure

| JSON Schema | Meaning | Jotl | TS / TSDoc | Usage |
|---|---|---|---|---|
| `type: "string"` | String | `string`, or the component omitted | ᵀ `string` | Components such as `text` `url` `image` are also built on it, see the [Jotl syntax specification](jotl.md#built-in-components) |
| `type: "number"` | Number | `number` | ᵀ `number` | |
| `type: "integer"` | Integer | `integer` | ᵀ `number` + ᴾ `@asType integer` | `integer` at positions that cannot carry a comment (array elements, `Map` values, tuple positions, union branches) is dropped with `JOTL2002`, unless `typiaTags` is enabled |
| `type: "boolean"` | Boolean | `boolean` | ᵀ `boolean` | |
| `type: "null"` | null | `nullable: true` | ᵀ `null`; a nullable union is written `(A \| B) \| null`, and the parentheses keep the inner `oneOf` / `anyOf` when read back | Merged into `type: [T, "null"]` for basic types, otherwise `anyOf: [T, {type: "null"}]` |
| `type: "object"` | Object | `{ ... }` or `map` | ᵀ `interface` / `{ ... }` | |
| `type: "array"` | Array | `array[...]` | ᵀ `T[]` / `[A, B]` | |
| `{}` (unconstrained) | Any value | `any` | ᵀ `unknown` | |
| `properties` | Object fields | The fields in `{ key: T }` | ᵀ Interface members | For key naming rules see the [Jotl syntax specification](jotl.md#names) |
| `required` | Names of required fields | Required when written with `:` and without `?`; `key?: T` and a bare `key(label)` are optional | ᵀ Whether the member has `?` | In declaration order; omitted when empty |
| `additionalProperties` (schema) | Value of extra keys | `map` | ᵀ Index signature `[key: string]: T` | |
| `additionalProperties: false` | No extra keys allowed | `closed: true` | ᴾ `@closed` on `money` `bigint` value objects; otherwise — | Only on the object type itself, not at a reference site |
| `items` | Array elements | `array_item` or a body; `false` for a tuple without `*` | ᵀ `T[]` | Metadata of the element itself goes in `item_meta` |
| `prefixItems` | Positional elements | `array[array_item: 'tuple'] { 0: A  1: B }` | ᵀ Tuple `[A, B]` | |
| `const` | Fixed value | Single-member enum `enum{ a }`; the discriminator of a discriminated union | ᵀ Literal type | The outer schema carries `type` (normalization rule 4) |
| `enum` | Set of values | Unlabeled `enum{ a b }` | ᵀ Union of literals | Multi-selects (`enum[multiple: true]`) get `uniqueItems: true` automatically |
| `oneOf: [{ const, title }]` | Labeled enum | `enum{ a(Alpha) b(Beta) }`; members may carry `description` | ᵀ Union of literals + ᴾ `@enumTitles {"a":"Alpha"}`, with member descriptions in ᴾ `@enumDescriptions` | Used when at least one member has a label or description |
| `oneOf` | Matches exactly one branch | `union[discriminator: 'kind'] {...}` | ᵀ Union `A \| B`, with branch titles in ᴾ `@branchTitles` | See the [Jotl syntax specification](jotl.md#union) |
| `anyOf` | Matches at least one branch | `union[union_item: 'A\|B']` | ᵀ Union `A \| B` | Written the same as `oneOf` in TS; decided again by the discriminability conditions when read back |
| `allOf` `not` `if` `then` `else` | Composition and conditionals | Reference branches of a discriminated union compile to `allOf: [{$ref}]`; otherwise — | Reference branches are ᵀ intersection types `X & {...}`; otherwise — | Validated as usual; when every member of `allOf` is a schema object, it is merged into this node before rendering (see `mergeAllOf` in [`packages/form/src/core/schema-node.ts`](../../packages/form/src/core/schema-node.ts)); otherwise the node, like `not` and `if`, degrades to the `json` widget (F7; for the decision table see `UNSUPPORTED_KEYWORDS` in [`packages/form/src/core/schema-shape.ts`](../../packages/form/src/core/schema-shape.ts)) |
| `propertyNames` | Constraints on key names | `map[key_meta: {...}]`, only `pattern` `minLength` `maxLength` | — | |
| `patternProperties` `dependentRequired` `dependentSchemas` `contains` `minContains` `maxContains` `unevaluatedItems` `unevaluatedProperties` | Other structural keywords | — | — | Validated as usual; `patternProperties` and `dependentSchemas` also make the node degrade to `json` |

## Constraints

In Jotl, constraints are all written as metadata after the component, `component[keyword: value]`; for which components accept them see the [Jotl syntax specification](jotl.md#metadata-keys).
In TS, they are all ᴾ protocol tags named after the keyword.

| JSON Schema | Meaning | Jotl | TS / TSDoc | Usage |
|---|---|---|---|---|
| `minLength` `maxLength` | Minimum / maximum string length, counted in code points | `string[maxLength: 20]` | `@maxLength 20` | |
| `pattern` | Regular expression (ECMA-262, not implicitly anchored) | `string[pattern: '^\\d+$']` | `@pattern` + the regex in backticks | |
| `minimum` `maximum` | Inclusive lower and upper bounds | `number[minimum: 0]` | `@minimum 0` | |
| `exclusiveMinimum` `exclusiveMaximum` | Exclusive lower and upper bounds | `number[exclusiveMaximum: 100]` | `@exclusiveMaximum 100` | |
| `multipleOf` | Must be an integer multiple of the number | — | `@multipleOf 0.01` | Use `decimals` to limit decimal places and `money` for amounts |
| `minItems` `maxItems` | Minimum / maximum number of array items | `array[maxItems: 5]` | `@maxItems 5` | Arrays and multi-selects allow an empty array by default; write `minItems: 1` when it must not be empty; for tuples it is the number of required positions |
| `uniqueItems` | No duplicate elements | `array[uniqueItems: true]` | `@uniqueItems` (no value) | Added automatically for multi-selects |
| `minProperties` `maxProperties` | Minimum / maximum number of object keys | `map[maxProperties: 10]` | `@maxProperties 10` | |

## Content

| JSON Schema | Meaning | Jotl | TS / TSDoc | Usage |
|---|---|---|---|---|
| `format` | String format (`email` `uri` `date` `color` and others) | Components such as `email` `url` `date`, or `string[format: 'email']` | ᴾ `@format email` | Validated by ajv-formats; `color` is a format defined by Jotl |
| `contentMediaType` | Media type of the string content | `richtext` (`text/html`), `jsontext` (`application/json`) | ᴾ `@contentMediaType text/html` | Other media types go through the `schema` metadata |
| `contentEncoding` | Encoding of the string content (such as `base64`) | — | ᴾ `@contentEncoding base64` | |
| `contentSchema` | Structure of the string content after parsing | The body of `jsontext` or `json_item` | — | Jotl treats it as an assertion: `application/json` text is parsed first and then validated against it, see `@jotl/data` |

## Non-standard keywords

The following keywords appear in generated schemas but are not part of the JSON Schema 2020-12 standard; only entry points are listed here:

| Keyword | Origin | Jotl | TS / TSDoc |
|---|---|---|---|
| `x-ui` | Jotl, see the [x-ui specification](x-ui.md) | Metadata `widget` `props` `hidden` `order` `groups` `layout` `columns` `root_if` `node_if` `variants` `decorator` `summary` `thousands`, plus `rules` `widgets` on the root entry only | ᴾ `@widget name` when there is only `widget`, otherwise ᴾ `` @ui `{...}` ``; for array elements, ᴾ `@itemWidget` / `@itemUi` on the array property; the root's `rules` become ᴾ `` @rules `[...]` `` on the root type, and the root's `widgets` (extension component modules) become ᴾ `` @widgets `{...}` `` |
| `x-deprecatedReason` | Jotl | The reason in `deprecated: 'reason'` | The body of `@deprecated reason` |
| `errorMessage` | ajv-errors | `errorMessage: '...'` / `errorMessage: {...}` | ᴾ `@errorMessage JSON` |
| `x-decimals` | Jotl, maximum number of decimal places | `decimals: n` | — |
| `x-valueFormat` | Jotl, storage format of dates and times | `value_format` | ᴾ `@valueFormat` |
| `x-decimalRange` | Jotl, range for `money` and `bigint` `value`s compared as exact decimals | `minimum` `maximum` and the like (as strings) on `money` `bigint` | ᴾ `@decimalRange {"minimum":"0"}` on `money` `bigint` value objects |
